## 1. Цель

Поднять конверсию **«запрос → первый файл»** за счёт замены welcome/consent «можно прислать документы» на **микрозадачу по делу**:

- два конкретных документа (по умолчанию ИЛС + трудовая);
- зачем нужны;
- срок;
- кнопка с персональной secure-ссылкой на экран загрузки;
- напоминания 24 ч / 3 дня;
- статусы задачи в CRM (отдельно от шаблонного `checklist_items`).

**Не цель этого ТЗ:** оптимизация таблицы `documents`, OCR, Яндекс.Диск, пересчёт пенсии.

Технический долг учёта вложений (нормализация `document.bin`, backfill) — отдельный трек (PR #39 и последующий `--apply`), параллельно, но **не блокер** продуктового A/B.

## 3. MVP: что видит клиент

### 3.1 Карточка задачи (не «раздел Documents»)

> **Нужно для проверки вашего стажа**  
> Загрузите, пожалуйста:  
> 1. Выписку из индивидуального лицевого счёта (ИЛС).  
> 2. Все заполненные страницы трудовой книжки.  
>
> Можно фото или PDF прямо здесь.  
> После получения проверим комплект и напишем, достаточно ли для начала анализа.  
>
> **Срок:** желательно до `ДД.ММ.ГГГГ`.  
> **Кнопка:** «Загрузить документы»

Правила копирайта:

- не обещать перерасчёт / сумму (см. `submission-position.md`);
- не писать «мы подадим в СФР»;
- не требовать юридическую классификацию файла клиентом;
- PDF не обязателен; фото — нормально;
- если нужен 1 документ — карточка говорит «1 документ», не общий шаблон на 3.

### 3.2 Тексты сообщений MAX

**Первое (группа B):**

```text
Здравствуйте, {Имя}!

Чтобы проверить ваш страховой стаж и понять, есть ли основания обратиться в СФР,
нам нужны два документа:

1) выписка ИЛС;
2) фото всех заполненных страниц трудовой книжки.

Их можно сфотографировать на телефон и отправить через безопасную форму.
После получения специалист проверит комплект и напишет, чего ещё не хватает.

Это обычно занимает 3–5 минут.

[Загрузить документы]
```

**Напоминание +24 ч:**

```text
{Имя}, напоминаем о документах для проверки стажа.

Пока не получены:
• выписка ИЛС;
• трудовая книжка.

Если документы сейчас не под рукой, ответьте «помощь» — подскажем,
где получить ИЛС и как сфотографировать трудовую книжку.

[Загрузить документы]
```

**Напоминание +3 дня:**

```text
{Имя}, без документов мы не сможем перейти к проверке стажа по вашему делу.

Можно отправить обычные фотографии страниц — PDF не обязателен.
Если удобнее, ответьте на это сообщение — специалист поможет выбрать способ передачи.

[Загрузить документы]
```

После каждой успешной загрузки (чат или secure page):

- «Получено: 1 из N»;
- при полном комплекте: «Комплект отправлен на проверку».

## 4. Персональная ссылка (secure action)

### 4.1 Формат

Использовать уже заложенный контур `secure_links` (`purpose` включает `upload` в `secure_links/token.py`):

```text
https://{PUBLIC}/s/{token}
```

или явный query для Mini App / web fallback:

```text
https://{домен}/max/documents?case={case_id}&task={task_id}&token={signed}
```

Канон MVP: **один raw token** в path (как consent / view_pdf), без ФИО/СНИЛС/телефона в URL.

### 4.2 Правила безопасности

- доступ только по подписанному токену (pepper / `SECURE_LINK_*`);
- привязка: `case_id` + `purpose=upload` (+ `task_id` в meta);
- TTL: **7–14 суток** (рекомендация MVP: 14), с безопасной переиздачей;
- `max_uses`: высокий или «по TTL» (загрузка нескольких файлов);
- в аналитике — только `token_prefix`, не raw;
- после открытия: сразу карточка задачи + кнопка загрузки, **без** логина и поиска раздела;
- если MAX Mini App недоступен — та же ссылка открывает мобильный web secure page.

Реализация опирается на:

- `src/sfrfr/secure_links/` (`issue_*`, `purpose=upload`);
- флаги `SECURE_ACTION_LINKS_ENABLED` / связанные;
- приём файлов → существующий `create_quarantine_document` / portal upload.

## 5. Объект «Задача по документам» (CRM)

Отдельно от шаблонного `checklist_items`.

| Поле | Пример / значения |
|------|-------------------|
| `case_id` | UUID дела |
| `task_type` | `initial_document_pack` |
| `requested_documents` | `ils`, `employment_record`, опц. `sfr_decision` |
| `status` | `draft` → `sent` → `opened` → `upload_started` → `received` → `under_review` → `accepted` \| `revision_needed` \| `expired` \| `cancelled` |
| `requested_at` / `due_at` | timestamps |
| `preferred_channel` | `max_miniapp` |
| `deep_link_sent_at` | |
| `first_upload_at` / `completed_at` | |
| `reviewed_by` | staff user id |
| `reminder_count` / `last_reminder_at` | |
| `source` | `max_miniapp` \| `web_cabinet` \| `staff_import` \| `email` |
| `experiment_group` | `A` \| `B` (для A/B) |

### 5.1 Идемпотентность и повторная отправка

Для одного `case_id` одновременно допускается **не более одной активной**
`document_request_task` с `task_type = initial_document_pack`.

**Активные статусы:**  
`draft`, `sent`, `opened`, `upload_started`, `received`, `under_review`, `revision_needed`.

(Неактивные / терминальные: `accepted`, `expired`, `cancelled`.)

**При повторном «Отправить запрос» / `document-task-send`:**

1. если активная задача есть — **переиспользовать её** (не создавать вторую);
2. безопасно **переиздать** secure-link (`purpose=upload`, старый токен revoke / expire);
3. обновить `deep_link_sent_at` (и при необходимости `due_at`);
4. **не** сбрасывать `first_upload_at` и историю событий воронки;
5. вторую задачу того же типа создавать **только** по явной команде
   «Создать новую задачу» (отдельный флаг/CLI), например после `accepted` /
   `cancelled` / `expired`.

Так клиент не получает разные ссылки и противоречивые напоминания, а A/B
не считает одно дело несколько раз.

Миграция: новая таблица `document_request_tasks` (имя уточнить в PR) + RLS/service role как у cases.
Частичный уникальный индекс (или аналог в приложении): не более одной строки
с `task_type = initial_document_pack` в активном статусе на `case_id`.

В админке (минимум после первого теста): колонка/бейдж статуса задачи на карточке дела; кнопка «Отправить запрос документов».

## 6. A/B на 20–30 дел

| Группа | Сообщение |
|--------|-----------|
| **A** | Текущий welcome/consent + общее «можно прислать» |
| **B** | Карточка задачи §3 + secure-кнопка |

**Главная метрика (7 дней):**

\[
\text{Конверсия в первую загрузку}
=
\frac{\text{дел с first\_upload\_at за 7 дней}}
{\text{дел с sent запросом}}
\]

Дополнительно: `opened`, `upload_started`, полный комплект, время до первого файла, ответы «помощь», причины отказа (ручная метка ops).

Операционный сигнал успеха: в B заметно больше первых загрузок, чем в A (ориентир: A ≈ 0–1, B ≈ 4–6 из 15 при равных выборках).

Отбор дел: `preferred_channel=max_miniapp`, есть MAX user, нет полного комплекта, статус intake / early pipeline. Исключить тестовые и без согласия ПДн.

## 7. События аналитики (без ПДн в payload)

Для каждого `case_id` / `task_id` (хеш или UUID):

`task_sent` → `link_opened` → `upload_cta_click` → `file_picker_opened` → `upload_success` \| `upload_failed` → `pack_complete` → `staff_accepted`

В событии: timestamp, device class, mime class (`pdf`/`image`/`other`), size bucket, error_code.  
**Не** класть ФИО, СНИЛС, имена файлов с ПДн, сырой token.

## 8. План реализации (срезы)

### Срез 1 — MVP без полной админки (достаточно для A/B)

1. Таблица `document_request_tasks` + сервис create/send/remind
   (**идемпотентность §5.1**: одна активная задача на дело, переиздание ссылки).
2. `issue_upload_link` (purpose=`upload`) + secure page «задача + загрузка».
3. Отправка текста §3.2 в MAX с кнопкой URL.
4. Хук: успешный upload (MAX chat или secure page) → обновить `first_upload_at` / статусы / «1 из N».
5. Reminder job (+24 ч, +3 дня) по `reminder_count` (только для активной задачи).
6. CLI или admin-only: `sfrfr document-task-send --case-id … --group B`
   (повторный вызов = resend по §5.1, не duplicate).
7. Флаг `DOCUMENT_REQUEST_TASK_ENABLED` (default off).

### Срез 2 — CRM

- UI статуса в admin;
- кнопка «Запросить документы»;
- отчёт A/B за 7 дней.

### Вне scope среза 1

- HEIC / автосжатие (желательно срезом 1.1, если блокирует мобильных);
- полный заменитель checklist;
- Яндекс.Диск;
- merge/apply PR #39 (отдельное подтверждение).

## 9. Критерии готовности MVP

- [ ] Можно отправить задачу B одному делу из CLI/admin.
- [ ] Клиент по кнопке открывает карточку без логина (валидный token).
- [ ] Загрузка фото/PDF увеличивает счётчик задачи и пишет в Storage/`documents`.
- [ ] Напоминания уходят только если статус &lt; `received`.
- [ ] В логах/аналитике нет raw token и ПДн.
- [ ] Флаг выключен → поведение как сейчас (группа A).
- [ ] A/B на 20–30 дел запущен, отчёт через 7 дней.
