# ТЗ-27: обратная связь после PDF-диагностики

**Версия:** 1.0  
**Дата:** 2026-08-23  
**Статус:** к реализации (схема + ops DONE; UI/автокасания — по этапам)  
**Сайт / продукт:** `proverkastaza.ru` · сервис «Проверка стажа»  
**Связано:** [playbook-diagnosis-feedback.md](../marketing-sales/playbook-diagnosis-feedback.md) · [стандарт PDF](../marketing-sales/playbook-diagnosis-result-standard.md) · [ТЗ-19](19-yandex-reviews-feedback.md) · [marketing consent](../marketing-sales/playbook-marketing-consent.md)

---

## 1. Цель

Проверять **понятность и практическую полезность** результата диагностики, а не собирать формальные отзывы в момент выдачи.

Главный критерий успеха: клиент понимает **первый шаг** и может начать действовать.

## 2. Не является целью

- просить публичный отзыв сразу при выдаче PDF;
- смешивать сервисный опрос с рекламой;
- собирать СНИЛС, паспорт, номера документов, медсведения, сканы или подробности ИЛС в опросе;
- публиковать отзыв без отдельного согласия;
- слать касания при «не беспокоить» / после отзыва согласия на ПДн (по политике).

---

## 3. Сценарии

1. **После выдачи PDF** — сервисное сообщение с вариантами:  
   «Всё понятно» / «Нужна помощь с планом» / «Есть вопрос».  
2. **Через 2–3 дня** — если PDF выдан (и по возможности открыт), ответа нет → **черновик** сообщения с вариантами 1–4.  
3. **Через 10–14 дней** — один сервисный запрос о выполнении первого шага плана (если «сам» / «не успел»).  
4. **После ответа клиента** — автоподсказки и напоминания пересчитываются или отменяются.  
5. **После подтверждения ознакомления** — мини-анкета качества (3–4 вопроса).  
6. **Публичный отзыв** — только после положительной оценки + отдельное согласие (ТЗ-19).

Все автоматические сообщения сначала как **черновики**, подтверждает сотрудник.

---

## 4. Поля данных

Таблица `diagnosis_feedback` (1:1 с `cases`):

| Поле | Тип / смысл |
|------|-------------|
| `pdf_issued_at` | Выдача PDF клиенту |
| `pdf_opened_at` | Открытие (если технически доступно; иначе null) |
| `feedback_status` | `none` · `nav_pending` · `nav_sent` · `understood` · `need_help` · `has_question` · `survey_done` · `do_not_disturb` |
| `clarity_score` | 1–4 |
| `expectation_match` | `yes` · `partial` · `no` |
| `useful_section` | `periods` · `missing_docs` · `action_plan` · `ils_explain` · `other` |
| `improvement_comment` | Короткий текст (без ПДн в аналитике) |
| `first_plan_step_status` | `done` · `blocked` · `deferred` |
| `difficulty_category` | `ils` · `labor` · `archive` · `sfr` · `docs` · `other` |
| `follow_up_service_requested` | bool |
| `review_publication_consent` | `none` · `requested` · `granted` · `denied` |
| `review_consent_version` | Версия текста согласия |
| `review_consent_at` | Момент согласия |
| `touch2_due_at` / `touch3_due_at` | Плановые сервисные касания |
| `touch2_sent_at` / `touch3_sent_at` | Факт отправки |

При загрузке документа `doc_type=diagnosis_report` сотрудником — выставлять `pdf_issued_at` (если ещё пусто) и планировать касания; статус навигации — `nav_pending` до подтверждённой отправки сообщения.

---

## 5. Ограничения

- Не запрашивать в форме СНИЛС, паспорт, номера документов, медсведения, сканы, подробности ИЛС.  
- Не публиковать отзыв без отдельного согласия.  
- Не отправлять рекламу по этому сценарию без согласия на рекламу.  
- При отзыве согласия на ПДн — прекратить необязательные опросы по политике.  
- В аналитических срезах — **без ПДн**.

---

## 6. Аналитика

- открытие PDF (`pdf_opened_at` / прокси);  
- ответ на запрос обратной связи;  
- понятность (`clarity_score`);  
- выполнение первого шага;  
- частые `difficulty_category`;  
- запрос сопровождения;  
- причины неудовлетворённости (`expectation_match=no`).

---

## 7. Приёмка

- [ ] Опрос отделён от запроса публичного отзыва.  
- [ ] Клиент может ответить одной кнопкой/цифрой.  
- [ ] Нет ПДн в аналитических срезах.  
- [ ] Нельзя отметить «опубликован» без `review_publication_consent=granted`.  
- [ ] Напоминания не уходят при `do_not_disturb` / «не беспокоить».  
- [ ] Автотекст — черновик до подтверждения сотрудником.  
- [ ] При `diagnosis_report` фиксируется `pdf_issued_at`.
