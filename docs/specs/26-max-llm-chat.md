# ТЗ-26: LLM-чат в личном диалоге MAX

**Статус:** реализовано (go): провайдер — **DeepSeek V4 Flash в Yandex AI Studio** (`llm.api.cloud.yandex.net`), не YandexGPT.  
Свободный текст → сразу `reply_to_free_text` (не queue); очередь остаётся у portal/вложений.  
Health: `llm_chat_enabled`, `llm_chat_model`, `bot_owned` (отдельно от ops LLM).  
Флаги: `MAX_LLM_CHAT_ENABLED`, `MAX_LLM_CHAT_MAX_TURNS`, `MAX_BOT_OWNED_ENABLED`, `MAX_BOT_OWNED_PAY_LINK`.  
**Дата:** 2026-08-11 / обновлено 2026-09-09 (bot_owned funnel)  
**Связано:** [ТЗ-20](20-max-private-chat-funnel.md), [ТЗ-08](08-knowledge-rag.md), [ТЗ-12](12-amocrm.md) (резерв), [ТЗ-06](06-integrations-and-security.md), [ТЗ-25](25-max-ops-bot.md)  
**История фикса:** `docs/history/2026-09-09-max-bot-owned-funnel.md`

## 1. Проблема

Клиенты пишут свободным текстом и ждут ответа «как у человека».  
По ТЗ-20 первый сценарий — дерево кнопок без LLM: предсказуемость и меньше ПДн в чате.  
Канон (с 2026-09): при флаге on свободный текст идёт в LLM сразу после rule-reply; nudge кнопок — fallback при выкл. флаге / ошибке / ПДн.

## 2. Цель

Дать опциональный **ограниченный LLM-ответ** в личном чате MAX, если клиент не жмёт кнопки, без превращения бота в свободного пенсионного консультанта. Документы: предпочтительно кабинет на сайте; вложение в чате принимает handler (не LLM).

## 3. Out of scope (жёстко)

- Обещания сумм пенсии / гарантия перерасчёта.
- Подача заявления от имени клиента или «мы подадим в СФР».
- Приём сканов, СНИЛС, ИЛС, паспортных данных в чат.
- Автозамена специалиста: LLM не закрывает ветку «Позвать специалиста».
- Хранение полного свободного текста пользователя в `max_intake` / CRM (как в ТЗ-20).
- Дообучение модели на клиентских диалогах.

## 4. Когда включать LLM

| Условие | Действие |
|---|---|
| `/start`, callbacks intake | Без LLM — дерево кнопок (ТЗ-20) |
| Первое свободное сообщение после welcome | Можно короткий LLM-ответ **или** nudge кнопок (feature-flag) |
| Повторный свободный текст | LLM с лимитом ходов; кнопки всегда в ответе |
| Клиент явно просит человека / «Позвать специалиста» | Только оператор, LLM off |
| Production без ключей / флаг выкл | Только nudge (текущее поведение «2») |

Предлагаемый флаг:

```text
MAX_LLM_CHAT_ENABLED=0|1
MAX_LLM_CHAT_MAX_TURNS=5
```

Провайдер — `LLMClient` → DeepSeek V4 Flash в Yandex AI Studio (не YandexGPT), без новых облаков вне РФ без решения по ТЗ-15.

## 5. Поведение ответа

5. Системный промпт фиксирует:
   - роль: вежливый агент «Проверка стажа»;
   - позиция подачи: готовим документы и план, подаёт клиент через СФР/МФЦ/Госуслуги, решение только СФР;
   - предсказуемый следующий шаг + «зачем»;
   - запрет юридсоветов «под ключ», сумм, гарантий;
   - если нужны документы — предпочтительно кабинет **на сайте**; файл в чате принимает handler;
   - основные кнопки intake не ломать; soft-кнопки только дополняют;
   - в конце всегда предложить кнопки или специалиста.
   Канон текста: [`docs/MAX/prompt-agent-client-chat.md`](../MAX/prompt-agent-client-chat.md).
2. Контекст модели: последние N обезличенных реплик + текущий шаг intake (enum), без ФИО/СНИЛС/файлов.
3. Ответ ≤ ~500–700 символов, русский язык, без markdown-таблиц.
4. К ответу всегда прикреплять клавиатуру текущего шага intake (как `free_text_nudge`).
5. При детекции ПДн в тексте (эвристика: длинные цифры, «СНИЛС») — не слать в LLM; ответить шаблоном «лучше не писать цифры в чат; документы — предпочтительно кабинет на сайте; файл сюда — примем».
6. Не обещать «кабинет в MAX» (его нет и не будет) / «кабинет в этом чате».

## 6. Данные и аудит

- В БД/файлах intake — по-прежнему только enum-поля.
- Логи: `action=max_llm_reply`, `intake_step`, длина текста, без тела сообщения в production.
- Метрики: `max_llm_reply`, `max_llm_blocked_pdn`, `max_llm_fallback_nudge`, `max_operator_from_llm`.
- При эскалации — очередь сотрудника / кабинет (не amo; amo в резерве), без текста переписки в CRM-карточке.

## 8. Критерии готовности

1. При `MAX_LLM_CHAT_ENABLED=0` поведение как сейчас (nudge + кнопки).
2. При `=1` свободный текст получает ответ модели + кнопки шага; без создания дела на каждый ход.
3. Сообщения с явными ПДн не уходят в LLM.
4. «Позвать специалиста» работает независимо от LLM.
5. В ответах нет обещаний выплат и нет формулировок «мы подадим за вас».
6. Приёмка на staging с ручным чек-листом 10 типовых реплик.

## 9. Решение (зафиксировано 2026-09)

1. LLM на свободном тексте — **сразу** (`reply_to_free_text`), в т.ч. до создания дела.
2. Лимит ходов — `MAX_LLM_CHAT_MAX_TURNS` (счётчик `llm_turn_count` на intake; после лимита — короткий nudge + кнопки, не молчание).
3. Провайдер — DeepSeek V4 Flash / AI Studio; биллинг YC разблокирован (см. `docs/ops/yandex-cloud-billing-unblock.md`).
4. Промпт канон — [`docs/MAX/prompt-agent-client-chat.md`](../MAX/prompt-agent-client-chat.md) ↔ `CLIENT_CHAT_SYSTEM`.

## 10. Режим bot_owned (2026-09-09)

Пока `intake.status != handed_to_operator` и `MAX_BOT_OWNED_ENABLED=1`:

- бот ведёт воронку (кнопки + фразы → `intake:` payload);
- старт и файлы **не** шлют ops/staff-задачу на каждый шаг;
- после ingest — короткий статус комплекта без OCR-текста;
- комплект ИЛС+трудовая → черновик DIAG 3000 ₽ + ссылка на оферту в кабинете;
- pay link в MAX только после `contract_accepted` (`MAX_BOT_OWNED_PAY_LINK`, не глобальный `MAX_PAY_LINK_AUTO_SEND`).

После «Позвать специалиста» свободный текст **не** идёт в LLM (`waiting_for_staff`).
Диагностика 5/8 тыс. и PDF результата — человек.
