# ТЗ-11: блог публичного сайта

> Связано: [02-public-site-wordpress.md](02-public-site-wordpress.md), [10-landing-audit-and-implementation.md](10-landing-audit-and-implementation.md).

## 1. Назначение

Блог на WordPress — **справочник по проверке стажа**, а не лента новостей компании.

Цели:

| Цель | Как блог помогает |
|---|---|
| SEO | Запросы: ИЛС, неучтённый стаж, архивная справка |
| Доверие | Понятные инструкции для пенсионеров и родственников |
| Лиды | CTA в выбор канала MAX / веб-кабинет |
| Снижение нагрузки | Частые вопросы закрываются до чата |
| Бренд | Эксперт по разбору дела, не «гарант пенсии» |

Сайт продаёт услугу; блог **обучает и приводит** в `#kak-rabotat` / кабинет / MAX.

## 2. Границы

### Делает

- Отвечает на **один** вопрос на статью.
- Даёт чек-лист «что подготовить».
- Ведёт к услуге мягким CTA.
- Использует Schema `Article`; при FAQ-блоке внутри — допустим `FAQPage` на уровне страницы FAQ (не дублировать агрессивно).

### Не делает

- Не обещает повышение пенсии / конкретную сумму.
- Не выдаёт себя за СФР / «официальный сервис».
- Не принимает сканы, СНИЛС, паспорт (нет upload в WP).
- Не публикует ФИО и кейсы с ПДн.
- Не копирует чужие тексты и «юридические гарантии».

Дисклеймер в каждой статье (внизу):

> Не являемся СФР. Решение о перерасчёте принимает СФР. Материал носит справочный характер.

## 3. Рубрики и URL

```text
/blog/                              — список статей
/blog/slug-na-translite/            — статья
/blog/rubrika/ils/                  — выписка ИЛС
/blog/rubrika/stazh/                — стаж, трудовая, периоды
/blog/rubrika/dokumenty/            — справки, архив, МФЦ
/blog/rubrika/podacha/              — подача в СФР / Госуслуги
/blog/rubrika/dlya-rodstvennikov/   — помощь близким
/blog/rubrika/usluga/               — как устроен сервис (редко)
```

> WP: `category_base` нельзя ставить просто `blog` — иначе rewrite перехватывает URL статей и отдаёт 404. Префикс рубрик: `blog/rubrika`.

### Меню сайта

Блог не обязан быть в первой строке hero-меню. Варианты:

```text
Главная | Как это работает | Услуги | Вопросы | Статьи | Начать проверку
```

или пункт «Статьи» в footer + блок на главной «Полезное».

«Начать проверку» — контрастная CTA → `#kak-rabotat` (выбор MAX / веб-кабинет).

## 4. Шаблон статьи

1. H1 — вопрос читателя (как в поиске).
2. Короткий ответ (2–4 предложения) — суть сразу.
3. Кому статья полезна.
4. Пошагово (нумерованный список).
5. Какие документы понадобятся.
6. Частые ошибки.
7. Когда имеет смысл обратиться за разбором.
8. CTA: «Начать проверку» → `#kak-rabotat`.
9. Связанные статьи + ссылка на FAQ.
10. Дисклеймер.

Параметры:

- Объём: **800–1500** слов (для аудитории 60+ лучше короче и крупнее).
- Тон: «вы / ваш», простые слова; аббревиатуры расшифровывать при первом упоминании (ИЛС — …).
- Один H1; логичная H2/H3-иерархия.
- Уникальные title и description (Rank Math).

## 6. Воронка

```text
Поиск / ссылка
  → статья блога
  → готов действовать? → #kak-rabotat (MAX или кабинет)
  → ещё вопросы? → FAQ / другие статьи → снова CTA
  → дело только в MAX / кабинете (не на WP)
```

CTA в статье:

1. Основной: «Начать проверку» → `#kak-rabotat`.
2. Вторичный: «Читать FAQ» или «Услуги и тарифы».

Форму лида в конце статьи допускать **без файлов**; предпочтительно не дублировать форму на каждой статье — один CTA в канал.

## 7. Связь с другими контурами

| Контур | Роль |
|---|---|
| WordPress | Публичные статьи, SEO |
| FAQ | Короткие ответы; блог — развёрнуто |
| Кабинет / MAX | Документы и дело — только там |
| Knowledge / RAG ([08](08-knowledge-rag.md)) | Обезличенные кейсы **не копировать** в блог как есть; эксперт может сделать обобщённую статью без ПДн |

**Блог ≠ база знаний бота.** Блог — для людей и поиска; RAG — для ассистента внутри продукта.

## 8. Редакционные правила

1. Автор: «Редакция / эксперт сервиса»; дата публикации и **дата обновления** обязательны.
2. Статьи про подачу и отказы (P0) смотрит эксперт/юрист.
3. Запрещено: «гарантируем», «вернём», «официально от СФР», «100%».
4. Разрешено: «часто помогает проверить», «может повлиять», «решение за СФР».
5. Кейсы — только обезличенные, формулировка «пример ситуации».
6. Иллюстрации: схемы/иконки документов; без печатей, гербов, денег крупным планом.
7. Крупный шрифт, короткие абзацы; контраст текста достаточный для пожилых.
8. Не включать: комментарии к постам (спам + риск ПДн), рейтинги «звёзды гарантии», агрессивные pop-up.

## 9. Техника WordPress

- Тип: Записи (Posts) + рубрики §3.
- SEO: Rank Math (или один выбранный плагин) — title, description, Article schema.
- Хлебные крошки; список 6–9 карточек, пагинация.
- На главной: блок «Полезные статьи» — 3 материала из приоритетных рубрик.
- `sitemap.xml` включает posts; Search Console / Яндекс Вебмастер.
- Schema: не использовать `GovernmentOrganization`.
- Аналитика не должна слать ПДн в URL/события.

## 10. Процесс выпуска

```text
Идея (запрос из поиска / чата MAX)
  → черновик (редактор)
  → проверка фактов (эксперт)
  → дисклеймер + CTA
  → публикация
  → раз в 6 месяцев: актуализация дат и ссылок на Госуслуги/СФР
```

Метрики (без ПДн): просмотры, доскролл, клик по CTA «Начать проверку», переходы в MAX/кабинет.

## 11. MVP сдачи

1. Раздел `/blog/` + **4 статьи** (#1–#4 из §5).
2. Блок на главной «Читайте также».
3. Единый шаблон + дисклеймер.
4. CTA → `#kak-rabotat`.
5. FAQ ссылается на статьи («Подробнее»).

Далее: статьи #5–#12 и рубрика для родственников.

## 12. Критерии приёмки

- Нет обещаний результата и формулировок «официальный сервис СФР».
- Нет upload документов в формах блога.
- Каждая статья: дисклеймер, CTA на выбор канала, уникальные title/description.
- Рубрики и ЧПУ соответствуют §3.
- Кейсы без идентифицирующих данных.
- Инструкция для редактора: как публиковать и обновлять статьи (передаётся при сдаче лендинга, см. ТЗ-10 §9).
