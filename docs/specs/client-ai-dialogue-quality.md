# Качество клиентского ИИ-диалога — входной индекс

**Координация:** SFRFR-100 · **диалоговая волна:** SFRFR-110  
**Статус:** спецификация (документационный контур). Реализация и live-проверки принимаются отдельно.

## Источники истины (не дублировать)

| Тема | Канон | Не писать второй раз |
|---|---|---|
| Тексты при ошибке ИИ / сервиса | [`client-ai-error-response-catalog.md`](client-ai-error-response-catalog.md) | ops message-catalog — только краткие отсылки |
| Контракты переходов, частичные сбои | [`client-ai-transition-contracts.md`](client-ai-transition-contracts.md) | копипаст тех же запретов в QA |
| Доказательства, версии, доступ, аудит | [`client-ai-evidence-requirements.md`](client-ai-evidence-requirements.md) | отдельный «конкурирующий реестр» |
| Синтетические приёмочные сценарии ошибок | [`../qa/client-ai-error-scenarios.md`](../qa/client-ai-error-scenarios.md) | прод-данные, ПДн |
| Пробелы кода vs спека | [`../ops/client-ai-error-implementation-gaps-2026-10-24.md`](../ops/client-ai-error-implementation-gaps-2026-10-24.md) | объявлять реализацию «готовой» |

Сценарные карты 20.x (тревога, претензии, отказ этапа, обвинение в обмане и т.д.) ведутся в ветке/PR **SFRFR-110** (`docs/client-ai-dialogue-quality`). После слияния той волны этот индекс дополняется ссылками на § сценариев **без** переноса полных текстов сюда.

## Главный принцип

Исправление подтверждается **действиями и проверяемыми событиями**, не извинением и не намерением модели.

```text
Тип ошибки
+ подтверждённое состояние
+ проверенные последствия
+ фактически выполненные действия
→ клиентский текст
```

- Только документация.
- Без миграций, без изменения тарифов, сроков, юргarantий и полномочий.
