# Требования к доказательствам (ошибки, претензии, исполнение)

Канон. Индекс: [`client-ai-error-docs-index.md`](client-ai-error-docs-index.md).  
Не создавать второй конкурирующий реестр рядом с этим документом.

**Архитектурное ограничение:** новые таблицы и миграции — только после аудита пробела.  
Таблица `result_evidence` в продукте — про суммы/результат пенсии; **не** перегружать её журналом диалоговых доказательств.

## 1. Слои материала

| Слой | Пример | Не является |
|---|---|---|
| Исходный материал | Сообщение, документ, версия условий | Подтверждением «правды» само по себе |
| Системное событие | Создание работы, запуск, отправка | Намерением ИИ |
| Аналитический вывод | Интерпретация | Самоподтверждением при повторной генерации |
| Решение ответственного | Подтверждение / исправление / разрешение | Генерацией модели |

Вывод ИИ и одинаковый результат повторной генерации **не** доказывают правильность.

## 2. Связи

```text
Спорный пункт
↔ исходные сообщения и документы
↔ версия вывода
↔ событие проверки
↔ решение ответственного
↔ исправленная версия
↔ доказательство исполнения
↔ уведомление клиенту
```

Одно доказательство → несколько пунктов; один пункт → несколько источников.

## 3. Карточка (логическая схема)

Поля (persist — после аудита хранилища):

| Поле | Требование |
|---|---|
| Идентификатор | Устойчивый внутренний ID |
| Связь | Дело, заказ, обращение, спорный пункт |
| Тип | Сообщение / документ / событие / условия / расчёт / решение |
| Источник | Канал, система, автор в пределах доступных данных |
| Время | `event_at` и `ingested_at` / `registered_at` — раздельно |
| Версия | Документа, расчёта, шаблона, условий |
| Оригинал | Защищённая ссылка |
| Фрагмент | Существенная цитата / страница / запись с достаточным контекстом |
| Проверка | Что, кем/чем, когда |
| Ограничения | Неполнота, нечитаемость, нет контекста |
| Зависимости | Какие выводы/действия опираются на материал |
| Доступ | Роли |
| Хранение | По утверждённой политике |

### Роли (раздельно)

- кто сообщил сведения;
- откуда материал;
- кто загрузил;
- кто/что проверил;
- полномочия проверяющего.

Загрузка сотрудником ≠ подтверждение содержания. Генерация модели ≠ экспертная проверка.

## 4. Хронология

Хранить: время события (если известно), получения, регистрации, источник времени, автор операции, связь с предыдущей версией.  
Поздняя запись — явный `late_entry`. Не подставлять время регистрации вместо неизвестного времени действия.  
Не добавлять отсутствовавшие события задним числом. Не перезаписывать оригинал, чтобы скрыть ошибку; исправление связывать с оригиналом.

## 5. Статус доказательства

| Статус | Значение |
|---|---|
| Получено | Сохранён; содержание не проверено |
| Доступно для чтения | Файл/сообщение извлечено |
| Проверено в указанном объёме | Есть запись конкретной проверки |
| Оспаривается | Зафиксированное противоречие |
| Заменено новой версией | Связь версий сохранена |
| Недоступно / повреждено | Не использовать как проверенный источник |

Техническая «файл открывается» ≠ «документ достоверен».

## 6. Минимум по типу спора

| Спор | Сохранить |
|---|---|
| Обещали прибавку | Сообщение с контекстом, дата, условия на момент покупки |
| Проверка не запускалась | История состояний и запусков, не только текущий статус |
| Расчёт неверный | Входы, метод, версия, допущения, результат |
| Не выдали отчёт | Версия файла, события передачи/доставки, доступность |
| Скрыли доплату | Описание и цена на момент заказа, сообщения до оформления |
| Период прочитан неверно | Исходное изображение, OCR-версия, исправление |
| Действие без согласия | Согласование, полномочия, параметры, результат |

Скриншот — один из материалов, не полная история события автоматически.

## 7. Воспроизводимость ИИ-вывода

Фиксировать при поддержке системы: версия модели/политики, шаблона, ссылки на материалы, инструменты и результаты, итоговый ответ, версия расчётного механизма.  
Не хранить скрытые рассуждения модели. Не требовать побитового повтора генерации.

## 8. Минимизация и защита

- Оригинал — в защищённом контуре.
- В задачах/событиях — внутренняя ссылка + необходимый фрагмент с контекстом.
- Не публиковать документы, токены, контакты, полные платёжные id, временные подписанные URL в публичных системах.
- Перед выдачей — права текущего получателя.
- GitHub, отчёты, тесты — только обезличенное.
- Срок хранения и удаление — по политике и проверенным требованиям, не произволом ИИ.

## 9. Аудит существенных операций

Фиксировать факт (без секретов и полного содержимого документов):

```text
Просмотр чувствительного · Экспорт · Изменение связи с делом
Создание версии · Смена актуальности · Решение
Изменение прав · Удаление / ограничение хранения
```

Клиентский диалог и ИИ **не** вправе незаметно править историю. Полномочные правки — по процессу с фиксацией.

## 10. Два представления выдачи

1. **Клиенту** — понятный итог, его материалы, основания исправления, открытые вопросы.  
2. **Уполномоченной проверке** — хронология, версии, решения, доказательства исполнения.

Оба исключают данные других клиентов, секреты и внутреннее, не предназначенное получателю.

## 11. Идемпотентность и сбои

- Идентификаторы операций против дублей.
- Нет фиктивных ссылок при сбое хранения.
- Сообщение «исправлено» / «принято» — только после проверки результата операции.
