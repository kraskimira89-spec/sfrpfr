# ТЗ-27: AI-помощник специалистов в MAX Ops

**Статус:** в коде  
**Дата:** 2026-08-12  
**Связано:** [ТЗ-25](25-max-ops-bot.md), [ТЗ-08](08-knowledge-rag.md), [ТЗ-26](26-max-llm-chat.md) (клиентский LLM — отдельно, не смешивать)

## 1. Цель

Специалист в служебном контуре MAX задаёт вопрос → бот **«Проверка стажа-Ops»** отвечает с опорой на базу знаний проекта (нормы, кейсы RAG-ready, ops-справка, позиция подачи).

## 2. Где отвечает

| Место | Триггер |
|-------|---------|
| Личный диалог с ops-ботом | Свободный текст (кроме `/start`, `/help`, приветствий) |
| Канал **«Проверка стажа — команда»** | Упоминание бота (`@id8905998693_3_bot` / имя) **или** `/ask …` |

Без триггера в канале — **молчание** (не спамить redirect’ом).

## 3. Знания

- `knowledge/*.md` + `knowledge/cases` (только verified/template) через `KnowledgeRetriever`
- Канон позиции: `scripts/assets/copy/submission-position.md`
- Сводка контура: `knowledge/ops_project.md`
- Опционально whitelist коротких ops/spec файлов (без секретов)

## 4. Env

```text
MAX_OPS_LLM_ENABLED=1          # 0 — выключить AI-ответы
MAX_OPS_LLM_MAX_CHARS=3500     # обрезка ответа
```

LLM: тот же `LLMClient` (Yandex / fallback DeepSeek), что кабинет.

## 5. Правила ответа

- Не обещать перерасчёт/выплаты; решение только СФР.
- Клиент подаёт сам (позиция submission).
- Не повторять сырые ПДн; перед LLM — `redact_for_llm`.
- Если данных мало — сказать, чего не хватает; пометить проверку экспертом.

## 6. Критерии готовности

1. DM ops: вопрос → осмысленный ответ при настроенном LLM.  
2. Канал: без mention/`/ask` — нет ответа.  
3. `MAX_OPS_LLM_ENABLED=0` → прежнее поведение (redirect в DM).  
4. Health: `ops_llm_enabled` отражает флаг.
