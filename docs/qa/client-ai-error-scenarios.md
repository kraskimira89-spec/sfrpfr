## F. Исполнимые сценарии (follow-up ревью #262)

Формат: id · предусловие · действие · ожидание · запрет.

### F01. Отказ регистрации ≠ успех

| Поле | Содержание |
|---|---|
| ID | F01 |
| Предусловие | Клиент требует претензию; вызов регистрации вернул подтверждённый отказ/сбой; обращение сохранено |
| Действие | Сформировать ответ о статусе регистрации |
| Ожидание | Текст класса «Зарегистрировать не удалось»; указаны следующий шаг и что сохранено |
| Запрет | «Обращение зарегистрировано»; выдуманный номер; «претензия принята» |

### F02. Завершение сопровождения ≠ закрытие пенсионного вопроса

| Поле | Содержание |
|---|---|
| ID | F02 |
| Предусловие | Сопровождение по услуге можно завершить; пенсионный итог в СФР не подтверждён |
| Действие | Закрыть контур сопровождения / коммуникации по согласованным критериям |
| Ожидание | В итоге явно: пенсионный вопрос остаётся открытым; причины и дальнейший маршрут сохранены |
| Запрет | «Пенсионный вопрос решён / закрыт»; «вопрос полностью решён» |

### F03. Исправленный результат дела при открытом системном дефекте

| Поле | Содержание |
|---|---|
| ID | F03 |
| Предусловие | Ошибка в деле клиента исправлена и persist ок; системная причина (шаблон/баг) ещё в работе |
| Действие | Выдать актуальную версию клиенту и уведомить |
| Ожидание | Клиент получает исправленный результат; tech-дефект остаётся открытым до своей проверки |
| Запрет | Ждать полного устранения причины перед выдачей безопасного результата; объявлять системную причину устранённой |

### F04. Неопределённость без успешной отметки ограничения

| Поле | Содержание |
|---|---|
| ID | F04 |
| Предусловие | Ошибка подтверждена; влияние на расчёт неизвестно; установка `needs_recheck` / ограничения **не** сохранилась |
| Действие | Ответ клиенту о состоянии |
| Ожидание | Допустимо: «Пока не установлено, повлияло ли это на…»; без утверждения, что результат отмечен/ограничен |
| Запрет | «Результат отмечен как требующий проверки» / «использование ограничено», если мера не применена; молчание вместо честной неопределённости |

## A–D. Приёмочный чек-лист (не исполнимые кейсы)

Ниже — сжатые ожидания для обзора. Для автоматизации разворачивать в формат F.

### A. Формулировки и состояния

| ID | Ожидание |
|---|---|
| Q-E01 | Подозрение → «требует проверки», не «ошибка подтверждена» |
| Q-E02 | После persist можно «Исправлено»; до — нельзя |
| Q-E03 | Нет фраз: «всё правильно», «полностью решён», «деньги вернутся» без фактов |
| Q-E04 | «Вы неправильно поняли» отсутствует |
| Q-E05 | Пустые `[поля]` и `needs_recheck` / `EVIDENCE_*` не уходят клиенту |

### B. Кейсы каталога (выборочно)

| ID | Кейс | Must | Must not |
|---|---|---|---|
| Q-E10 | E01 дата 1987→1985 | наша ошибка; зависимые на проверке | изменение пенсии подтверждено |
| Q-E11 | E02 сумма | нельзя считать подтверждённой | прибавки не будет |
| Q-E12 | E03 ложный running | сопоставление со статусом | правка текста = работа сделана |
| Q-E13 | E04 оплата | номер при успехе **или** честный сбой регистрации | авто-возврат; отказ как «зарегистрировано» |
| Q-E14 | E08 «пропущенный период» | слишком категорично | зеркальный «точно учтён» без оснований |
| Q-E15 | E15 handoff | регистрация ≠ назначение | «специалист уже занимается» без факта |
| Q-E16 | E16 выдача | доступ ≠ ознакомление | выдача завершена при битом доступе |
| Q-E17 | E19 платёж | неизвестный исход = не успех и не отказ | повторное списание без сверки |
| Q-E18 | E20 чужие данные | защищённый маршрут | «данные удалены, риска нет» |

### C. Переходы

| ID | Ожидание |
|---|---|
| Q-T01 | Претензия регистрируется без полной доказанности ошибки |
| Q-T02 | Access-check не удаляет обращение |

## E. Критерий пакета

Для любого примера из каталога E01–E21 и кейсов F01–F04:

1. Что система **знает** (события)?  
2. Что **вправе сказать** клиенту?  
3. Какое **действие** необходимо?  
4. Чем подтверждается **исполнение**?
