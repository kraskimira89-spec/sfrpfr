**Статус:** research / prep

Официальная документация: [dev.vk.com](https://dev.vk.com/) · [API methods](https://dev.vk.com/method) · [VK ID / OAuth](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/start-integration/auth-flow-web)

## 1. Зачем API в этом проекте

| Задача | Нужен ли API сейчас | Комментарий |
|--------|---------------------|-------------|
| Вести сообщество вручную | нет | UI сообщества достаточно на старте |
| Черновики постов агентом | нет (файлы в `docs/VK/`, `scripts/assets/…`) | Автопостинг пакетом **не** делаем по аналогии с MAX |
| Лид-форма → amo | желательно позже | webhook / выгрузка лидов Ads + ручной/скриптовый импорт |
| Статистика постов | опционально | `stats.get` / кабинет сообщества |
| Модерация комментариев | опционально | правила + ручные ответы на старте |
| Логин «Войти через VK» на сайте | **не приоритет** | вход в кабинет — текущий контур SFRFR |

**Вывод на P0:** сообщество и органика — без кода. API — когда появятся стабильный поток лидов из VK Ads и потребность в синхроне с amo.

## 2. Продукты VK, которые трогаем

1. **Сообщество (группы)** — витрина, посты, ответы.  
2. **VK Реклама (ads.vk.com)** — кампании, лид-формы, ERID.  
3. **Callback API / Long Poll** — события сообщества (новое сообщение, комментарий, лид) — только после политики «не принимать документы».  
4. **VK ID** — не смешивать с приёмом пенсионных документов.

Продвижение канала MAX через VK Рекламу оптимизируется на клики; считать диалоги / оплату отдельно (`research-audience-channels-2026-08.md`).

## 3. Минимальный контур интеграции (когда созреет)

```text
VK Ads lead form
  → webhook / poll → FastAPI (предпочт.) или n8n self-hosted P2
  → amoCRM lead (source=vk, UTM_*)
  → оператор пишет в MAX / звонит
  → кабинет SFRFR (согласие, документы)
```

Канон интеграций: [automation-stack-ru.md](../ops/automation-stack-ru.md). Make.com / Albato **не** используем.

Не класть в amo и не логировать: СНИЛС, ИЛС, сканы, текст решения СФР.

Поля лида — как в playbook §6: имя, контакт, «за себя/близкого», тип вопроса, согласие.

## 4. Технический чеклист (будущий)

1. Создать приложение на [dev.vk.com](https://dev.vk.com/) (тип под задачу: сообщество / ads).  
2. Права (scope) — **минимум**: управление сообществом / статистика / ads (что реально нужно).  
3. Токен сообщества vs пользовательский — не путать; сервисный токен не коммитить.  
4. Callback: подтверждение строки, секретный ключ, белый список IP/дока VK.  
5. Идемпотентность лидов (повтор webhook).  
6. Журнал событий без ПДн документов.  
7. Связь UTM из объявления с полями amo `UTM_SOURCE`…`UTM_TERM`.

Имена переменных (пример, без значений):

```text
VK_GROUP_ID=
VK_GROUP_TOKEN=
VK_CALLBACK_SECRET=
VK_CALLBACK_CONFIRMATION=
VK_ADS_CABINET_ID=
```

Файл-пример позже: `secrets/vk.env.example` — **только после решения владельца**, не раньше.

## 5. Методы / области API (ориентир)

Не копировать сюда полный справочник — сверять актуальную доку.

| Область | Примеры методов / продуктов | Зачем |
|---------|------------------------------|-------|
| Стена | `wall.post`, `wall.get` | публикация (осторожно; предпочтение ручной/полуручной) |
| Сообщения сообщества | `messages.*` | автоответ «без сканов → MAX» |
| Статистика | `stats.get`, insights кабинета | отчётность |
| Реклама | Ads API / кабинет ads.vk.com | кампании, лиды |
| Лид-формы | кабинет + API лидов (см. help ads) | импорт в amo |
| Callback | `message_new`, `wall_reply_new`, lead events | реакция без polling |

Автопубликация коммерческих постов скриптом — **только с явным флагом владельца**; по умолчанию черновик в markdown.

## 6. Безопасность и комплаенс

- Маркировка рекламы и **ERID** — обязательны для paid (`ads.vk.com` help ORD).  
- Рекламодатель = юрлицо ООО «ПОД ПРИСМОТРОМ» (реквизиты как на сайте / в оферте).  
- Не собирать через API то, что запрещено в лид-форме.  
- Комментарии с попыткой прислать паспорт/ИЛС — шаблон отказа + ссылка на MAX/кабинет.  
- Не обещать перерасчёт в автоответах бота.
