# Карточка amo: что видит оператор

**Для кого:** оператор продаж / квалификации.  
**Связь:** [how-we-work-amocrm.md](how-we-work-amocrm.md) · [sales-pipeline-amocrm.md](sales-pipeline-amocrm.md) · [playbook-operator-new-lead-cheatsheet.md](playbook-operator-new-lead-cheatsheet.md) (1 стр.) · `docs/marketing-sales/playbook-sales-qualification.md`

## Правило одной строки

В amo — **связь, сделка, статусы и чеклист документов по названиям**.  
Сканы, тексты, СНИЛС, ИЛС, OCR, ссылки Storage — **только в кабинете SFRFR** (кнопка «Ссылка на дело SFRFR»).

Позиция подачи: готовим документы и план — подаёт клиент через СФР/МФЦ/Госуслуги; решение принимает только СФР.

## 1. Чеклист полей в карточке сделки

### Всегда смотреть (рабочий блок)

| В карточке (рус.) | Код | Зачем оператору |
|-------------------|-----|-----------------|
| ID дела (SFRFR) | `CASE_ID` | Связь с кабинетом / admin |
| Ссылка на дело SFRFR | `SFRFR_CASE_URL` | Открыть дело и документы |
| Диалог MAX (ответ клиенту) | `MAX_DIALOG_URL` | Запасной путь: admin → «Написать в MAX» |
| Как ответить в MAX | `MAX_REPLY_HINT` | **Основной:** amo → **Чаты** (виджет MAX). См. [ops-amocrm-max-widget.md](ops-amocrm-max-widget.md) |
| MAX user_id | `MAX_USER_ID` | ID клиента в MAX |
| Статус пайплайна SFRFR | `PIPELINE_STATUS` | Что уже в SFRFR (не путать с этапом воронки amo) |
| Канал клиента | `CHANNEL` | MAX / кабинет / сайт… |
| Источник лида | `SOURCE` | Откуда пришёл |
| Согласие на связь | `CONSENT` | Можно ли писать / звонить |
| Имя + телефон + email | стандарт контакта | Связь (без сканов) |

### Квалификация и маркетинг (если заполнено)

| В карточке | Код | Зачем |
|------------|-----|--------|
| Первый источник | `FIRST_SOURCE` | Атрибуция |
| Последний источник | `LAST_SOURCE` | Атрибуция |
| Вариант лендинга | `LANDING_VARIANT` | Какой оффер видел |
| Сегмент аудитории | `AUDIENCE_SEGMENT` | Север / льгота / … |
| Регион (корзина) | `REGION_BUCKET` | Гео-сегмент |
| Реферальный код | `REFERRAL_CODE` | Партнёр / реферал |
| Тип проблемы | `PROBLEM_TYPE` | Короткий ярлык кейса |
| Причина потери | `LOSS_REASON` | При отказе / LOSS (не путать с «Ожидаем клиента» после чек-листа) |

### После чек-листа ИЛС (заметка, не файлы)

Статус **«Ожидаем клиента»** ≠ LOSS. Шаблон: [ops-amocrm-task-templates.md](ops-amocrm-task-templates.md).  
Канон касаний: [`playbook-sales-clarity-funnel.md`](../marketing-sales/playbook-sales-clarity-funnel.md) §5в.  
После ответа — препятствие и один шаг: **§5г** (микроворонка в заметке).

```text
Чек-лист отправлен: …
Напоминание №1 / №2: …
Причина ожидания: ИЛС | трудовая | решение семьи | нет связи | другое
Подэтап: ИЛС не получена | ИЛС получена | ориентировка | диагностика предложена | думает/семья | …
Препятствие: …
Одно действие / кто / к дате / как поймём:
Следующий контакт: …
Не беспокоить: да | нет
```

Наводящие вопросы (для сотрудника): clarity-funnel §5г.  
Создание отдельных custom fields под эти строки — **UI владельца** (по желанию); до этого достаточно заметки.

### После выдачи PDF-диагностики

[playbook-diagnosis-feedback.md](../marketing-sales/playbook-diagnosis-feedback.md) — сначала понятность / первый шаг, **не** отзыв сразу.

```text
PDF выдан: …
PDF открыт: …
Ознакомление: да | нет
Понятность: 1–4
Ожидания: да | частично | нет
Первый шаг плана: выполнен | сложность | отложен
Тема сложности: ИЛС | трудовая | архив | СФР | документы | другое
Сопровождение запрошено: да | нет
Отзыв: не запрашивался | запрошен | получен | опубликован с согласием
Не беспокоить: да | нет
```

### Не показывать / не трогать оператору

| Что | Почему |
|-----|--------|
| UTM (`utm_medium` …) | Системные поля amo, уже скрыты; заполняет API |
| Даты оплат / success fee (черновики) | `is_api_only`; до юр. модели не в работе |
| Поля «файл», СНИЛС, паспорт, ИЛС | **Запрещено** заводить и заполнять |

### Этап воронки amo

Отдельно от `PIPELINE_STATUS`: колонка воронки («Новый лид» → …).  
Двигать этап по факту контакта / оплаты / документов **в кабинете**, не по «файлам в amo».

## 2. Перечень документов (только названия и статус)

В **заметке / задаче / поле «Тип проблемы»** или в чек-листе задачи оператора фиксируйте **имя документа + статус**, без цитат и без вложений.

### Статусы (в тексте заметки)

```text
нет | запрошен | в кабинете | на проверке | ок | не нужен для кейса
```

### Базовый пакет (почти всегда)

| # | Документ (название) | Статус | Где смотреть содержимое |
|---|---------------------|--------|------------------------|
| 1 | Выписка ИЛС (Госуслуги / СФР) | … | Кабинет SFRFR |
| 2 | Трудовая книжка (сканы разворотов) **или** сведения о трудовой деятельности (электронные) | … | Кабинет |
| 3 | Согласие на обработку ПДн / работу в кабинете | … | Кабинет (факт согласия) |

### По ситуации (добавлять в список, не в файлы amo)

| # | Документ (название) | Когда спрашивать |
|---|---------------------|------------------|
| 4 | Справки работодателя / правопреемника / архива | Пробелы стажа, переименования, «нет в ИЛС» |
| 5 | Военный билет / справки о службе | Военная служба в стаже |
| 6 | Документы по северному / льготному стажу | Север, вредность, льготные списки |
| 7 | Решение / отказ СФР, переписка по делу | Уже было обращение / отказ |
| 8 | Свидетельства о браке / смене ФИО | Расхождение ФИО в документах |
| 9 | Иные подтверждения периодов (учеба, уход и т.п.) | Если период важен для кейса |

### Отдельный коммерческий флаг (не файл)

| Флаг в заметке | Смысл |
|----------------|--------|
| Трудовая: печатная / от руки | Квалификация объёма |
| Тяжёлый Word (100 ₽/разворот) | После осмотра сканов **в кабинете** — отдельный счёт; см. `playbook-trudovaya-word-table.md` |

## 3. Шаблон заметки оператора (копировать)

```text
Связь: [дозвон / MAX / email] — [дата]
Кейс: [за себя / за родственника]; пенсия: [уже / ещё нет]
Фокус: [ИЛС-стаж / север-льгота / документы / отказ СФР]

Документы (только статус):
- ИЛС: …
- Трудовая / эл. сведения: … ; почерк: [нет / да]; объём: [лёгкий / тяжёлый?]
- Согласие/кабинет: …
- Доп.: …

Следующий шаг: [диагностика / кабинет / счёт Word / LOSS: причина]
Дело: открыть по SFRFR_CASE_URL
```

**Не писать в заметку:** номера СНИЛС, серии паспорта, суммы пенсии «как обещание», куски OCR, ссылки на Storage.

## 4. Мини-чеклист открытия карточки (30 секунд)

1. Есть `CASE_ID` и открывается **Ссылка на дело SFRFR**?
2. Контакт и `CONSENT` позволяют связаться?
3. Этап amo соответствует факту (новый / связались / документы / оплата)?
4. В заметке есть **перечень документов со статусами**, без вложений?
5. Сканы смотрю **только в кабинете**, не прошу прислать в amo / MAX-канал?

Если пункта 1 нет — эскалация: sync / `amocrm-sync`, не вести «пустое» дело только в CRM.
