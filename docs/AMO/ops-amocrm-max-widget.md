# amoCRM: виджет MAX (переписка из amo)

**Решение:** вариант **1** — оператор отвечает клиенту **из интерфейса amo** (раздел **Чаты**), бот — **клиентский** «Стаж и пенсия».

**Не путать с:**

| Контур | Бот | Где |
|--------|-----|-----|
| Клиентский (канон для ответов из amo) | «Стаж и пенсия» · `id8905998693_1_bot` | amoMARKET → MAX + `MAX_BOT_TOKEN` на VPS |
| Ops / сотрудники | «Проверка стажа-Ops» · `id8905998693_3_bot` | вход в admin, уведомления — **не** в виджет amo |
| Личный / тестовый бот | любой другой | **удалить** из виджета amo |

Канон кодовой sync SFRFR→amo: [tz-12-amocrm.md](tz-12-amocrm.md). Поля `CASE_ID`, `SFRFR_CASE_URL`, `MAX user_id` — по-прежнему обязательны.

---

## Зачем

- Оператор пишет клиенту **в том же окне amo**, без переключения на admin (admin остаётся запасным путём и для документов).
- Сообщение уходит клиенту в **его** чат с ботом «Стаж и пенсия» — не в ваш личный чат с ботом.

---

## Настройка (администратор amo, один раз)

### 1. Открыть виджет

1. `https://ВАШ_ПОДДОМЕН.amocrm.ru/amo-market/` → найти **MAX** (от amoCRM).
2. **Установить** / **Открыть** → вкладка **Описание**.

Официальная справка: [MAX как источник в amo](https://www.amocrm.ru/support/incoming_leads/max).

### 2. Подключить **клиентский** бот

1. На [business.max.ru/self](https://business.max.ru/self) → **Чат-боты** → бот **«Стаж и пенсия»** (`id8905998693_1_bot`).
2. **Интеграция** → скопировать **токен** (тот же, что `MAX_BOT_TOKEN` на VPS — **не** ops-токен).
3. Вставить в поле виджета MAX в amo → **Добавить**.

### 3. Убрать лишние боты

- Удалить из списка **«Проверка стажа-личный бот»** и любые тестовые боты.
- В списке должен остаться **один** бот — клиентский «Стаж и пенсия».

### 4. Проверка

1. С тестового MAX-аккаунта написать клиентскому боту `/start`.
2. В amo: **Чаты** (или иконка сообщений) — появился диалог.
3. Ответ из amo доходит клиенту в MAX.

Если диалог не появился — проверить токен и модерацию бота на business.max.ru.

## Как работает вместе с SFRFR

```text
Клиент → бот «Стаж и пенсия» → webhook SFRFR → дело в Supabase
                              ↘ sync API → сделка amo (CASE_ID, MAX user_id, …)
Клиент пишет снова → amo Чаты (виджет MAX) + наш handler (intake/уведомления)
Оператор отвечает → из amo Чаты ИЛИ admin «Написать в MAX» (оба через клиентский бот API)
```

| Источник сделки | Кто создаёт |
|-----------------|-------------|
| Заявка с сайта / API SFRFR | **Наш** `POST /api/public/leads` → amo |
| Первое сообщение только в MAX | SFRFR sync при intake; amo виджет — **чат**, не дублируйте вручную вторую сделку |

**Правило оператора:** одна сделка = одно дело. Сверять **MAX user_id** и **CASE_ID**; не создавать ручную сделку «из чата», если уже есть sync из SFRFR.

## Инструкция оператору (ежедневно)

### Ответ из amo (основной способ)

1. Открыть **сделку** в воронке «Проверка стажа».
2. Проверить **MAX user_id** и **Ссылка на дело SFRFR** (документы — только в admin).
3. Открыть **Чаты** amo (левая колонка / иконка сообщений).
4. Найти диалог по **имени клиента** или **user_id** (из поля сделки).
5. Отправить текст — [playbook-operator-first-message-max.md](playbook-operator-first-message-max.md).
6. Закрыть задачу «Первый контакт» → этап **«Связались»**.

### Запасной способ

- Поле **«Диалог MAX (ответ клиенту)»** → кабинет admin → **«Написать в MAX»**.

### Нельзя

- Открывать `max.ru/id8905998693_1_bot` как «чат клиента» — это **ваш** личный чат с ботом.
- Подключать в amo ops-бот или «личный» бот.
- Просить сканы / СНИЛС / ИЛС в amo или MAX — только кабинет SFRFR.

---

## Безопасность

- Токен бота — только в amo (виджет) и `/opt/sfrfr/.env` (`MAX_BOT_TOKEN`), **не** в git и не в скриншотах.
- При утечке — перевыпустить на business.max.ru и обновить amo + VPS.
