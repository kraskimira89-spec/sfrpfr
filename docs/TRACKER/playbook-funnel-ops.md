# Playbook: ops-задачи по воронке клиентов

**Логическая очередь:** теги `funnel-*` в `SFRFR`.  
**CRM по конкретным людям:** только **amoCRM** (`docs/AMO/`).

## Назначение

Внутренние задачи: улучшить этап, починить SLA, дописать чеклист, баг sync колонки — **не** карточки клиентов с ПДн.

## Теги этапов

Согласовано с [../AMO/playbook-funnel-checklists-automation.md](../AMO/playbook-funnel-checklists-automation.md):

| Тег | Смысл |
|-----|--------|
| `funnel-lead` | новый лид / первый контакт |
| `funnel-qualify` | квалификация |
| `funnel-diag` | диагностика / оффер 3k |
| `funnel-docs` | документы в кабинете |
| `funnel-submit` | клиент подаёт сам (СФР/Госуслуги) |
| `funnel-result` | ожидание решения СФР |
| `funnel-review` | запрос отзыва |
| `funnel-loss` | отказ + работа с причинами LOSS (без ПДн) |

Дополнительно: `funnel`, `ops`.

## Что писать в issue

**Можно:** `case_id` (UUID), канал (web/MAX/VK), этап, чеклист, ссылка на admin без ПДн в URL-тексте, гипотеза SLA.

**Нельзя:** ФИО, телефон, email, СНИЛС, сканы, цитаты переписки с идентификаторами.

## Шаблон

**Summary:** `[FUNNEL] <действие> на этапе <тег>`

**Description:**

```markdown
## Цель
…

## Контекст
- этап: funnel-…
- case_id: <uuid или «N/A — системная задача»>
- канал: web | MAX | VK

## Чеклист
- [ ] …
- [ ] без ПДн в комментариях

## Done
…
```

## Граница с amo

| Где | Что |
|-----|-----|
| amo | сделка, контакт, задачи оператора по лиду, LOSS_REASON |
| Трекер | баг sync, доработка чеклиста этапа, метрика конверсии этап→этап, разовая ops без ПДн |

Если нужна работа «по этому клиенту» с телефоном/именем — **только amo**, не Трекер.
