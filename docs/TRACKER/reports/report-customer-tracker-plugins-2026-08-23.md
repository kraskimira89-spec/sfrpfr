## 5. Что ещё не в зоне разработки (ожидание / действия заказчика)

| Шаг | Кто | Статус |
|-----|-----|--------|
| Модерация версии платформой | Яндекс (Weavix / Tracker) | ⏳ обе версии в `IN_REVIEW` |
| Появление в каталоге организации | после approve модерации | ⏳ |
| Добавить / включить плагин в организации | **администратор org** | после модерации |
| Включить плагин себе / пользователям | сотрудники | после включения в org |
| Публичный каталог Трекера (всем организациям) | поддержка Яндекса + архив исходников | **не входило в текущий объём**; при необходимости — отдельное решение |

Пока версия в `IN_REVIEW`, плагин может отсутствовать в списке «установленных» в UI — это ожидаемо.

Временный доступ без каталога (для приёмки): отладка через **Настройки → Эксперименты → Отладка плагинов** и локальный `weavix debug`.

---

## 6. Ограничения и соответствие политике ПДн

- В задачах Трекера **не храним** СНИЛС, ИЛС, сканы, телефоны клиентов и т.п.  
- Мастер SFRFR: при признаках ПДн — предупреждение с подтверждением.  
- Качество STAZH: при признаках ПДн — **создание блокируется**.  
- Решение о пенсии / перерасчёте принимает только СФР; плагины помогают завести **внутреннюю** задачу команды.

---

## 7. Рекомендуемые следующие шаги заказчику

1. Дождаться смены статуса версии с `IN_REVIEW` (проверка: `weavix info` или UI каталога).  
2. Администратору организации: **Плагины → каталог** → добавить / одобрить оба плагина для org.  
3. Назначить 1–2 сотрудников на приёмку сценариев:  
   - мастер: задача в SFRFR / PUB / FUNNEL с нужными тегами;  
   - STAZH: задача качества без ПДн; попытка с ПДн — отказ.  
4. При необходимости вывода во **общий** каталог Трекера — отдельное ТЗ и обращение в поддержку Яндекса.
