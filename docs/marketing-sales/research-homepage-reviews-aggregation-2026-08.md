# Отзывы на главной: агрегация Яндекс + анкета + MAX

**Дата:** 2026-08-13  
**Статус:** P1 реализован (бейдж + очередь цитат; без смеси рейтингов)  
**Связано:** ТЗ-19, ТЗ-21, MVP `/anketa-otzyv/`, soft-ask MAX, бейдж Sprav

## Короткий вердикт

**Нельзя** «просто суммировать» три канала и автопубликовать всё на главной.

| Источник | Что это на самом деле | На главную как «отзыв»? |
|----------|------------------------|-------------------------|
| **Яндекс Карты / Бизнес** | Единственный канонический публичный отзыв с рейтингом | Да — **официальный бейдж** + ссылка; тексты — только цитаты после модерации |
| **Анкета `/anketa-otzyv/`** | Помощник: вопросы → черновик → клиент идёт в Яндекс | Нет как отдельный рейтинг. Да — только если клиент **явно разрешил** показ на сайте |
| **MAX кнопки `review:*`** | Тот же помощник в чате | То же: черновик ≠ опубликованный отзыв |

Иначе получится: дубли рейтингов, «фейковые» отзывы без публикации в Яндексе, риск ПДн и конфликт с ТЗ-18/19/21.

## Что уже есть

- Бейдж рейтинга Sprav: футер + `/kontakty/`  
  `https://yandex.ru/sprav/widget/rating-badge/82469923047?type=rating`
- ТЗ-21: *«Не писать вручную число отзывов или оценку на главной — только виджет Sprav или ссылка на Карты»*
- Запрет Schema `AggregateRating` без реальных данных (ТЗ-18/19)
- Поток сбора: completed → MAX/анкета → `/otzyv/` → Sprav

У Яндекса **нет стабильного публичного API** списка текстов отзывов для сайта. Есть бейдж рейтинга. Парсинг / cookie-сессии кабинета — хрупко и нежелательно для продакшена.

## Целевая модель (рекомендуется)

```text
                    ┌─────────────────────┐
  completed ──────► │ MAX / анкета        │  черновик (не публикуем на главной)
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │ Яндекс /otzyv/      │  ← канон рейтинга и «суммы» отзывов
                    └──────────┬──────────┘
                               ▼
              ┌────────────────┴────────────────┐
              │                                 │
     Бейдж Sprav (авто)              Цитаты на сайте (опционально)
     на главной + футер              только после gate
```

### На главной — два слоя

1. **Доверие / рейтинг (авто, без нашей «математики»)**  
   - Бейдж Яндекса  
   - Кнопка «Читать отзывы на Картах» / «Оставить отзыв» → `/otzyv/`  
   - Подпись: «Оценки и отзывы на Яндекс Картах»  
   - **Не** считаем свой средний из анкеты+MAX+Яндекс

2. **Цитаты (контент сайта)**  
   - 2–4 коротких текста «что говорят о сервисе»  
   - Источник в метаданных: `yandex` | `site_consent`  
   - Имя: только обезличенно («Клиент», «из Ноябрьска») — без ФИО, case_id, СНИЛС, сумм пенсии  
   - Автопубликация **только** после фильтров + (для не-Яндекс) явного согласия

## Как «суммировать» каналы правильно

| Канал | Роль в сумме | Как попадает на главную |
|-------|--------------|-------------------------|
| Яндекс | Даёт **рейтинг и число** (через бейдж) | Бейдж сам; тексты — ручной/полуавто выбор 4–5★ без ПДн |
| Анкета | Увеличивает шанс, что клиент **допишет в Яндекс** | Не отдельный счётчик. Опционально: чекбокс «можно показать цитату на сайте» → очередь модерации |
| MAX | То же | После черновика: «опубликовать на Яндексе» (обязательно) + позже «разрешить цитату на сайте» (опционально) |

Итог для посетителя: **одна правда о рейтинге = Яндекс**. Сайт показывает бейдж + безопасные цитаты, а не «у нас 47 отзывов из трёх систем».

## Автопубликация: что можно / нельзя

### Можно (P1)

1. Вставить бейдж на **главную** (сейчас он в футере/`kontakty` — усилить видимость).  
2. Блок «Отзывы»: бейдж + 0–N цитат из `site_reviews` (таблица/JSON).  
3. Cron / ручной импорт: оператор раз в неделю копирует 1–2 новых текста с Карт → модерация → publish.  
4. Фильтры перед publish:  
   - нет СНИЛС/паспорта/ФИО третьих лиц/сумм пенсии;  
   - нет «гарантировали перерасчёт» / «повысили пенсию»;  
   - нет призыва «ставьте 5»;  
   - длина 40–600 символов;  
   - для `site_consent` — флаг согласия.

### Нельзя

- Автопостить черновики анкеты/MAX на главную без согласия и без Яндекса.  
- Складывать оценки анкеты с рейтингом Яндекса в один «4.9».  
- Парсить Карты неофициальными скриптами как основу продакшена.  
- Schema `AggregateRating` с выдуманными или смешанными цифрами.  
- Связывать публичную цитату с `case_id` / ПДн.

### P2 (если очень нужна «автоиз Яндекса»)

- Исследовать официальные виджеты/экспорт в кабинете Sprav.  
- Если появится стабильный API — sync только `source=yandex`, тексты через тот же gate.  
- До этого — **не** строить бизнес-логику на скрапинге.

## MVP на главной (минимальный объём работ)

1. Секция после trust / перед тарифами:  
   - заголовок «Отзывы на Яндекс Картах»;  
   - iframe бейджа;  
   - ссылка «Смотреть / оставить отзыв» → `/otzyv/`;  
   - 1–3 статических или из файла цитаты (пока вручную).  
2. Таблица `site_reviews` (или JSON в WP): `id, text, source, rating?, published_at, status`.  
3. Админ/ops: `status=pending|published|rejected`.  
4. Анкета/MAX (позже): чекбокс согласия на цитату на сайте → запись `pending` (текст черновика), **рейтинг сайта не трогаем**.

## Согласие (для цитат не из Яндекса)

Короткий текст:

> Можно показать этот текст на сайте proverkastaza.ru без ФИО и без персональных данных. На рейтинг Яндекса это не влияет — отзыв на Картах публикуете вы сами.

Без галочки — только путь в Яндекс.

## Метрики

- Клики с главной на `/otzyv/` и Карты  
- Новые отзывы в Sprav (раз в неделю вручную)  
- Доля цитат `published` / `rejected`  
- Не KPI: «сколько черновиков сгенерировали» ≠ «сколько отзывов на сайте»

## Решение для владельца

**Рекомендуем Option A (канон Яндекс + цитаты с gate):**

1. Рейтинг на главной = только бейдж Яндекса.  
2. Тексты = модерируемые цитаты (сначала с Карт вручную; потом с согласия с сайта/MAX).  
3. Анкета и MAX остаются воронкой **в Яндекс**, а не вторым публичным рейтингом.

**Option B** («всё само складывается в один рейтинг») — отклонить: ломает ТЗ-21, SEO и доверие.
