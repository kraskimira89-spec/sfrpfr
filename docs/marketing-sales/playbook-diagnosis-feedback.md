## Принцип

Два шага:

1. **Понял ли человек результат и может ли сделать следующий шаг?**  
2. Затем — **насколько полезной была услуга.**

Не просить отзыв в момент выдачи PDF: клиент ещё не прочитал документ и часто в тревоге.

Главный вопрос не «Вам понравилось?», а: **«Вы понимаете, что делать первым шагом?»**

Качество услуги и понятная информация — базовое право потребителя; обратная связь проверяет выполнение обещанного результата, а не «понравилось ли общение»  
([Роспотребнадзор](https://www.04.rospotrebnadzor.ru/index.php/consumer-information/faq/5355-12112015.html)).

## Когда писать

| Момент | Тип | Содержание |
|--------|-----|------------|
| Сразу после выдачи PDF | Навигация | Варианты 1 / 2 / 3 (понятно / помощь с планом / вопрос) |
| Через 2–3 дня | Сервис (если открыл PDF, нет ответа) | Варианты 1–4; **черновик → сотрудник** |
| Через 10–14 дней | Сервис (если «сам» или «не успел») | Первый шаг плана: выполнен / сложность / отложил |
| После «документ изучен» | Мини-анкета качества | 3–4 вопроса цифрами |
| Только после положительной оценки | Публичный отзыв | Отдельное согласие на публикацию (ТЗ-19) |

Сервисные касания по **уже оплаченной и выданной** диагностике ≠ реклама.  
Не использовать их как повод рекламировать другие услуги без `marketing_consent`.

Автосообщения — сначала **черновик**, подтверждает сотрудник.  
Статус «не беспокоить» / отзыв согласия ПДн → стоп необязательных опросов.

## Разделить: качество · отзыв · реклама · база знаний

| Действие | Цель | Согласие |
|---|---|---|
| Оценка качества после услуги | Улучшить услугу, проверить понятность | В рамках обращения / договора (см. политику) |
| Публикация отзыва | Маркетинг | **Отдельное** явное согласие на публикацию |
| Реклама новых услуг | Продвижение | **Отдельное** согласие на рекламу |
| Обезличенный вывод в KB | Процессы | Внутренние правила обезличивания |

Не публиковать фамилию, фото, возраст, историю пенсии, диагноз, документы, цитаты без отдельного согласия  
([РКН / отметка согласия](https://rkn.gov.ru/press/news/news51712.htm)).

## Поля в карточке (заметка / БД)

```text
PDF выдан: дата / время
PDF открыт: дата / время (если доступно)
Подтверждение ознакомления: да / нет
Понятность результата: 1 / 2 / 3 / 4
Ожидания: да / частично / нет
Первый шаг плана: выполнен / сложность / отложен
Тема сложности: ИЛС | трудовая | архив | СФР | документы | другое
Запрошено сопровождение: да / нет
Отзыв: не запрашивался | запрошен | получен | опубликован с согласием
Не беспокоить: да | нет
```

Канон кода полей — [ТЗ-27](../specs/27-diagnosis-pdf-feedback.md).

## Если «не понял»

Не: «там всё написано».

```text
Спасибо, что сказали. Давайте разберём спокойно. Подскажите, какой раздел
оказался сложнее: периоды работы, недостающие документы или план действий?
Я объясню простыми словами и уточню, что можно сделать первым шагом.
```

Один и тот же вопрос у **трёх** клиентов → править шаблон PDF, не клиента.

## Если «не получил ожидаемого»

```text
Спасибо за честный ответ. Нам важно разобраться. Подскажите, пожалуйста,
чего именно не хватило: ясности по периодам, списка документов, плана действий
или объяснения следующего шага? Мы проверим результат по вашему делу.
```

Не спорить и не просить публичный отзыв. Внутренняя проверка качества; при недосдаче объёма — исправление по договору.

## Аналитика (без ПДн в срезах)

- доля открывших PDF;
- доля «план понятен»;
- частые непонятные этапы / `difficulty_category`;
- доля выполнивших первый шаг;
- переход к сопровождению — только когда объективно нужно;
- причины неудовлетворённости (`expectation_match=нет` + категория).
