# Поток отзыва: анкета → ИИ-черновик → клиент публикует в Яндексе

**Дата:** 2026-08-13  
**Статус:** рекомендация к целевому UX (лучше текущего «просто ссылка / вопросы без сборки текста»)  
**Связано:** ТЗ-19, `playbook-yandex-form-review-prompts.md`, `/otzyv/`, форма-помощник Forms

## Вердикт

**Да, так лучше.** Наводящие вопросы + черновик отзыва от ИИ + кнопка «Публиковать отзыв» (открыть Яндекс) — проще для клиента 55+ и честнее, чем «напишите сами».

Публикует **только клиент** в форме Яндекса. Мы не постим отзыв за него и не подставляем «пять звёзд».

## Почему сильнее текущего

| Сейчас | Предлагаемый поток |
|--------|-------------------|
| Ссылка `/otzyv/` или вопросы без сборки текста | Анкета простыми ответами |
| Клиент сам формулирует абзац | ИИ собирает складной черновик из **его** ответов |
| Легко бросить на пустой форме Картах | «Скопировать» + «Открыть отзыв на Яндексе» |

Яндекс Формы **не** умеют нормально: ИИ-черновик, кнопка копирования, наш LLM, контроль канона. Их можно оставить запасным каналом, но **основу** лучше держать у себя (страница на `proverkastaza.ru` или экран в кабинете / MAX).

## Целевой сценарий

```text
Дело completed
  → мягкое приглашение (как сейчас, без давления)
  → анкета (3–7 лёгких вопросов, без ПДн)
  → «Собрать текст отзыва» (ИИ)
  → черновик на экране + «Скопировать»
  → «Публиковать отзыв» → https://proverkastaza.ru/otzyv/
  → клиент вставляет текст в форму Яндекса и сам ставит оценку
```

### Вопросы анкеты (канон)

Те же, что в `review-prompt-questions.md` (минимум 3):

1. Чем помогли?  
2. Было ли понятно общаться?  
3. Что было удобно?  

Расширение — по желанию (зачем обратились, граница СФР, что улучшить).

### Правила для ИИ-черновика

- Писать **от первого лица** по ответам клиента; не выдумывать факты.  
- Без СНИЛС, паспорта, ФИО третьих лиц, сумм пенсии, «повысили пенсию».  
- Без призыва «ставьте 5».  
- Короткая пометка над черновиком: «Черновик по вашим ответам — можете править перед публикацией».  
- Канон подачи: мы готовим / подаёте вы / решает СФР — только если клиент это отметил в анкете.

### Кнопка «Публиковать отзыв»

1. Копирует текст в буфер (если браузер позволяет) **или** явно просит «Скопировать».  
2. Открывает `/otzyv/` (→ Sprav).  
3. Подсказка: «Вставьте текст в поле отзыва (Ctrl+V) и отправьте».

Глубокая подстановка текста в форму Яндекса по URL **ненадёжна** — не строить на ней.

## Где делать (рекомендация)

| Вариант | Плюсы | Минусы |
|---------|--------|--------|
| **A. Страница сайта** `/anketa-otzyv/` | Быстро, без логина, свой LLM | Нужна SmartCaptcha / антиспам |
| **B. Кабинет после completed** | Привязка к делу, меньше спама | Только для вошедших |
| **C. MAX-бот пошагово** | Там уже диалог | UX копирования хуже, чем на сайте |

**MVP:** A или B.  
Текущую Яндекс Форму-помощник — не развивать в ИИ; либо выключить из CTA, либо оставить как «только вопросы» без генерации.

## Границы (нельзя)

- Автопубликация отзыва от имени клиента.  
- Бонус / скидка за отзыв или за «звёзды».  
- Серия напоминаний (остаётся 1 авто + 0–1 ручное).  
- Просьба писать, что СФР повысил пенсию.  
- Хранить ПДн из анкеты дольше, чем нужно для черновика (или не хранить ответы — только одноразовый черновик в сессии).

## Метрики

- Открыл анкету  
- Сгенерировал черновик  
- Нажал «копировать» / «публиковать»  
- (опционально) появился новый отзыв в Sprav — вручную/раз в неделю  

Не обещать автоматическую сверку «наш клик = отзыв на Картах».

## Этапы внедрения

Согласовать поток с владельцем.

### P1 (MVP)

1. Страница или экран анкеты + генерация черновика (Yandex LLM / существующий ops LLM).  
2. Кнопки «Скопировать» и «Публиковать отзыв» → `/otzyv/`.  
3. После `completed` в MAX: ссылка на анкету вместо «голой» `/otzyv/` (или две ссылки: короткая и «помочь сформулировать»).

### P2

- Кабинет: кнопка «Оставить отзыв» на экране результата.  
- Мягкий A/B: только `/otzyv/` vs анкета.  
- Отключить или архивировать Forms-помощник из операторских шаблонов.
