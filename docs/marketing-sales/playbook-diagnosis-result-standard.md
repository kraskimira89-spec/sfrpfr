# Стандарт результата диагностики

**Статус:** канон продукта (MVP внедрения)  
**Дата:** 2026-08-23  
**Связано:** [clarity-funnel §4в](playbook-sales-clarity-funnel.md) · [выдача / MAX](../../scripts/assets/copy/diagnosis-result-delivery.md) · [шаблон](../../scripts/assets/templates/diagnosis-stazh-report.md)

Клиент платит не за «посмотрели документы», а за **понятный, проверяемый документ**, по которому он или родственник понимает: что учтено, где вопросы, чего не хватает и что делать дальше.

Справка: выписка ИЛС содержит сведения о пенсионных правах; через Госуслуги — электронно (часто в течение дня), через СФР/МФЦ сведения могут быть сформированы сразу. Для подтверждения стажа СФР опирается на персучёт и, при недостаточности, на документы о работе  
([СФР: получение сведений о пенсионных правах](https://sfr.gov.ru/grazhdanam/personificirovannyj_uchet/poluchenie_svedenij_o_pensionnyh_pravah/)).

---

## Название результата

**Не** называть: «Юридическое заключение», «Расчёт пенсии».

```text
Диагностика сведений о стаже и пенсионных документах
Информационно-документарный разбор
```

Подзаголовок:

```text
Подготовлено по документам, предоставленным клиентом.
Не является решением СФР, гарантией перерасчёта или расчётом размера пенсии.
```

`doc_type` в кабинете: **`diagnosis_report`** (подпись: «Результат диагностики»).

---

## Формат выдачи

1. PDF на **3–6** страниц простым языком (обязательный артефакт).  
2. Приложение: таблица периодов — если нужна.  
3. План действий на одной странице (внутри PDF или отдельный лист).  
4. Доступ через **защищённый кабинет**.  
5. Короткое сообщение в MAX: готов, где смотреть, следующий шаг (`diagnosis-result-delivery.md`).

Не выдавать итог только голосом, в переписке или фразой «мы всё посмотрели».

### Ops-цепочка (MVP)

```text
1. Скопировать scripts/assets/templates/diagnosis-stazh-report.md
2. Заполнить (без СНИЛС / паспорта / полного номера ИЛС в файле для пересылки)
3. python scripts/build_diagnosis_report_pdf.py path/to/filled.md
4. Admin → дело → Диагностика → загрузить PDF (doc_type=diagnosis_report)
5. Этап «Диагностика выдана» / pipeline audited|draft_ready
6. MAX: шаблон выдачи + ссылка в кабинет
```

Сборка PDF: pandoc + Edge/wkhtmltopdf (как шпаргалка оператора).

## Стандарт PDF (структура)

### 1. Титульный блок

```text
ДИАГНОСТИКА СВЕДЕНИЙ О СТАЖЕ
И ПЕНСИОННЫХ ДОКУМЕНТАХ

Дата подготовки: __.__.____
Дата актуальности сведений ИЛС: __.__.____
Номер дела: ПС-________
Сложность (внутр.): A | B | C | D
```

**Не** выводить для пересылки: СНИЛС, паспорт, полный номер ИЛС, избыточные ПДн.  
В кабинете ФИО/номер дела — только если нужны для идентификации; для родственника — сокращённое имя или обезличенная версия.

### 2. Короткий вывод (первая страница)

Человек понимает результат за минуту: проверено · учтено · требует уточнения · следующий шаг.

Маркеры статуса:

| Маркер | Смысл |
|--------|--------|
| Зелёный | Подтверждено представленными данными |
| Янтарный | Требует уточнения / доп. документа |
| Серый | Не относится / не проверялось |
| Красный | Документально выявлено **расхождение** (не «СФР неправ») |

### 3. Перечень изученных документов

Только реально изученные. Обязательная фраза:

> Выводы сделаны только по документам, перечисленным в этом разделе. Документы, которые не были предоставлены или не читаются, не оценивались.

### 4. Таблица периодов

Ядро результата. Статусы только из канона (см. шаблон).  
Запрещено: «должны включить», «гарантированно зачтут», «СФР обязан», «прибавка будет».

### 5. Расхождения и вопросы

3–7 пунктов по шаблону: наблюдение → почему важно → что может помочь → следующий шаг.  
Документы для подтверждения стажа зависят от периода (договоры, приказы, справки, трудовая, лицевые счета и т.п.) — без универсальных гарантий.

### 6. План действий

Исполняемый: шаг · кто · что · срок-ориентир · результат.  
Режим строки: самостоятельно / с поддержкой сервиса / решение внешнего органа.

### 7. Что сервис может сделать дальше

Честный блок: самостоятельно · с поддержкой (5 000 / 8 000 по объёму) · не входит.  
Цену следующего этапа **не** прятать в PDF как уже согласованную, если клиент ещё не согласился — указать как возможный следующий шаг с отсылкой к согласованию.

## Контроль качества (перед отправкой)

```text
□ Указана дата выписки ИЛС
□ Перечислены только реально изученные документы
□ Нет СНИЛС, паспортных данных и лишних ПДн
□ У спорных периодов есть даты и источник
□ Нет обещаний перерасчёта / увеличения пенсии
□ У каждого вопроса есть практический следующий шаг
□ В плане указано, кто выполняет действие
□ Не предложен платный этап там, где достаточно самостоятельного
□ Есть дисклеймер о компетенции СФР
□ Сложные дела (C/D): проверка вторым сотрудником
```

## Сегментация сложности (внутренняя)

Не юридическая квалификация — оценка трудозатрат и формата.

| Уровень | Признаки | Результат |
|---|---|---|
| **A** — простой | ИЛС и трудовая без явных расхождений | Короткая проверка + самостоятельный план |
| **B** — средний | 1–2 спорных периода, нужны справки | Таблица + план сбора |
| **C** — сложный | Архивы, ликвидация, север/льгота, отказ СФР | Расширенная таблица, приоритеты доказательств, оффер 5k/8k при объёме |
| **D** — вне формата | Суд, много работодателей, недоступные документы, нужны полномочия | Отдельная оценка → профильный маршрут |

В карточке / PDF: `Сложность: B`. Срок канона 3 р.д. — для A/B; для C владелец может согласовать иной срок **до** обещания клиенту.

## Первый стандарт внедрения (минимум)

1. Короткий итог на одной странице  
2. Таблица периодов  
3. 3–5 вопросов/расхождений  
4. План с ответственным  
5. Дисклеймер СФР  

После **10** диагностик — опрос:

> Какая часть результата была наиболее понятна и полезна? Чего не хватило, чтобы сделать следующий шаг?

Дорабатывать шаблон по ответам, не по предположениям.
