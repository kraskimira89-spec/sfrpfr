# Исследование: Цифровой ID MAX для SFRFR

**Дата:** 2026-08-12  
**Статус:** research / не к реализации без go владельца  
**Источники:** `docs/Инструкции по подключению/` (инструкция партнёра, API v1.5.8, тулкиты ритейл/культура)

## 1. Зачем смотрели

В пакете MAX для партнёров описан **Цифровой ID** — QR из приложения MAX вместо бумажных документов. Для торговых сетей это в основном **18+** и льготы на кассе. Для SFRFR интересно другое: в расширенном ответе API есть статус **`pensioner`**.

## 2. Что в пакете (кратко)

| Материал | Назначение для MAX-партнёра | Для SFRFR |
|----------|-----------------------------|-----------|
| Инструкция по подключению | Госкан / КСО / касса, токен на `business.max.ru` | Только шаги партнёрского кабинета и токена |
| Цифровой ID API v1.5.8 | `age-verification` + льготные статусы | **Основной документ** |
| Тулкиты торговых сетей | Плакаты 18+, радио, полки | Не брать as-is |
| Тулкит учреждений культуры | Льготы у касс/входа | Идея офлайн-мест (библиотеки, соццентры) — адаптация под канал/бот |
| QR КСО / размещение промо | Кассы самообслуживания | Не наш сценарий |

## 3. Выжимка API

### 3.1 Endpoint

- **Метод:** `GET`
- **URL (v1.5.8):** `https://ext-api2.max.ru/v2/business/pos/age-verification`
- **Auth:** заголовок `Authorization: <EXT_API_TOKEN>` (токен организации, не bot token)
- **Content-Type:** `application/json`
- **TLS:** 1.3+; нужны корневые сертификаты Минцифры: https://www.gosuslugi.ru/crt

### 3.2 Query

| Параметр | Обяз. | Смысл |
|----------|-------|--------|
| `session_id` | да | Строка из QR «Цифровой ID» в MAX. Формат вида `https://www.gosuslugi.ru/m…/{qr_id}?p=f`. При проверке шаблона достаточно префикса `https://www.gosuslugi.ru/m` |
| `verification_details` | нет | `true` — расширенные статусы; `false`/нет — только возраст |

### 3.3 Полезные поля при `verification_details=true`

| Поле | Для SFRFR |
|------|-----------|
| `adult.status` | Вторично (формально 18+) |
| **`pensioner.status`** | **P0-кандидат:** подтверждение статуса пенсионера без сканов в чат |
| `disabledPerson.status` (+ группа) | Позже: сегменты/скидки, не путать с решением СФР |
| `certificateLargeFamily` | Позже |
| `student.*` | Сейчас не приоритет |
| `raw_data` + `sign` | Аудит; не светить в UI; не класть в amo |

Ошибки: `400`, `401` (токен), `404` (нет Цифрового ID → направить в флоу создания в MAX), `429`, `500`.

### 3.4 Ограничения

1. QR **обновляется ~каждые 30 секунд** — UX только «отсканировал / вставил сейчас».
2. Токен партнёра живёт **~1 год**.
3. Это **не** `MAX_BOT_TOKEN` и **не** ops-бот: отдельная партнёрская платформа `https://business.max.ru/self`.
4. Логировать `session_id`, `request_id`, `sign` — без публикации ПДн.

## 4. Границы внедрения для SFRFR

### В scope (если go)

1. Опциональный шаг **в защищённом кабинете** после согласия: «Подтвердить статус пенсионера через Цифровой ID MAX».
2. Результат: флаг в деле (`pensioner_verified_via_max_digital_id` + timestamp + `request_id`), без обещания перерасчёта.
3. Секреты: `MAX_DIGITAL_ID_EXT_TOKEN` (имя черновое) только в `.env` / Lockbox — не в git, не в HTML.
4. Отдельное ТЗ продукта + юридическая проверка формулировок на экране.

### Out of scope

- Интеграция КСО, кассового ПО, ручных сканеров магазинов.
- Приём QR / статусов в **личном чате** MAX или канале (нарушает ТЗ-20/21/24).
- Замена выписки ИЛС, трудовой и загрузки документов в кабинете.
- Маркетинг «QR вместо паспорта на кассе» и промо 18+.
- Автоматическая подача в СФР / имитация Госуслуг.

### Позиция сервиса (обязательно на экране)

> Мы готовим документы, проект обращения и понятный план. Мы расскажем по шагам, но обращение через СФР, МФЦ или Госуслуги подаёте вы сами. Решение о пенсии и перерасчёте принимает только СФР.

Подтверждение `pensioner` через Цифровой ID — **не** решение СФР и **не** гарантия выплат.

## 5. Рекомендуемый порядок работ

| Этап | Действие | Результат |
|------|----------|-----------|
| 0 | Регистрация на `business.max.ru/self` (МСП/RuStore или `gov@max.ru` + ИНН) | `EXT_API_TOKEN` |
| 1 | Этот research + согласование границ с владельцем | go / no-go |
| 2 | Spike на staging: один вызов с тестовым QR | Понятен UX и 404-флоу |
| 3 | ТЗ: кнопка в кабинете, хранение флага, отказ в чате | Спека |
| 4 | Опционально: офлайн QR на **канал/бот** SFRFR (не Digital ID) для партнёров «культура/соц» | Рост подписок |

## 6. Связь с текущими ТЗ

- Усиливает доверие и снижает ПДн в чате: [ТЗ-20](../specs/20-max-private-chat-funnel.md), [ТЗ-21](../specs/21-trust-first-contact.md), [ТЗ-24](../specs/24-max-client-boundaries-home.md).
- Не путать с клиентским / ops-ботом ([ТЗ-25](../specs/25-max-ops-bot.md)): Digital ID API — отдельный контур.
- Документы дела — в личном чате MAX или кабинете на сайте (не amo, не форма WP).

## 7. Риски

| Риск | Митигация |
|------|-----------|
| Путаница «мы = Госуслуги/СФР» | Дисклеймер + бренд-правила |
| UX с QR 30 сек | Подсказка «откройте свежий QR» + повтор |
| Нет токена партнёра | Этап 0 блокирует код |
| Хранение лишних ПДн из `raw_data` | Хранить только boolean + request_id |
