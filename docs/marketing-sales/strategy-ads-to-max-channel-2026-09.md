# Стратегия: реклама → канал MAX → заявка в личный чат

**Дата:** 2026-09-22  
**Статус:** канон (подправка текущей модели CTA)  
**Связано:** [ТЗ-23](../specs/23-max-channel-promotion.md) · [ТЗ-20](../specs/20-max-private-chat-funnel.md) · [ТЗ-24](../specs/24-max-client-boundaries-home.md) · [playbook канала](playbook-max-channel-month-2026-08.md) · [bot_owned funnel](../history/2026-09-22-max-bot-funnel-docs-pay-plan.md)

## 1. Цель

Собрать аудиторию в **одном публичном канале MAX**, прогреть доверием и пользой, а заявку на разбор вести **из каждой публикации** в личный чат-бот — до результата по делу (диагностика → документы → сопровождение в рамках оферты).

```text
Реклама / охват / SEO-промо
        ↓
Подписаться на канал MAX  (MAX_CHANNEL_URL)
        ↓
Ежедневные посты (польза, без ПДн)
        ↓
Кнопка «Подать заявку» на КАЖДОМ посте
        ↓
Личный чат-бот (MAX_CHAT_URL)  ← bot_owned до результата
        ↓
Согласие / документы / оплата / сверка / план со специалистом
        ↓
Клиент подаёт в СФР сам; решение — только СФР
```

## 2. Что меняем относительно «как было»

| Было (ТЗ-20/23) | Стало (канон 2026-09) |
|-----------------|------------------------|
| Реклама и главный CTA сайта → **личный чат** | **Платный охват и промо** → **канал** (подписка) |
| Канал — вторичный (футер, после диалога) | Канал — **главная точка входа из рекламы** |
| CTA поста: «Уточнить ситуацию…» / иногда только URL | На **каждом** посте кнопка **«Подать заявку»** → личный чат |
| Личный чат = первый контакт с улицы | Личный чат = **заявка из канала** (+ органика с сайта допустима) |

Сайт **не ломаем**: блок «Как пользоваться MAX» остаётся (канал / чат / кабинет).  
Меняем приоритет **рекламы и промо-ссылок**, не запрещаем «Написать в чат» на главной для тёплого трафика.

## 3. Роли сущностей (обновлённые)

| Сущность | Роль в воронке |
|----------|----------------|
| **Канал MAX** | Подписка из рекламы; польза и доверие; **единственная кнопка заявки** на постах |
| **Личный чат-бот** | Заявка → диагностика FSM/LLM → документы/оплата → сверка → план; до результата по оплаченным шагам |
| **Кабинет на сайте** | Согласие, оферта, загрузка файлов, статусы (тот же `case_id`) |
| **Сайт / SEO** | Органика и объяснение услуги; мягкий CTA «Читать канал» + опционально чат |

## 4. Правила рекламы

1. **Целевая ссылка платного трафика** (Директ «на MAX», VK, посевы, QR в офлайне):  
   `MAX_CHANNEL_URL` = `https://max.ru/channel_proverkastaza`  
   UTM: `utm_source=…&utm_medium=cpc|cpm&utm_campaign=…&utm_content=channel`.
2. **Не** вести холодную рекламу сразу в `MAX_CHAT_URL` (дорого и без прогрева; обрыв «не понял, куда попал»).
3. Объявление обещает: «канал о стаже и ИЛС» / «подпишитесь — разборы без обещания перерасчёта», **не** «гарантируем прибавку».
4. Посадочная Директа на **сайт** допустима для поиска (интент «услуга»), но в первом экране и thank-you — **сильный CTA «Подписаться на канал MAX»**; кнопка чата — вторичная.
5. Метрика: цели `max_channel_click` (подписка/переход) и `max_chat_click` (заявка из канала/сайта) — см. `scripts/yandex_metrika_ensure_counter.py`.

---

## 5. Правила публикаций канала

1. **Каждый** пост в клиентский канал публикуется с кнопкой  
   **«Подать заявку»** → `MAX_CHAT_URL` (`cta_kind: chat`).
2. Если нужна статья на сайте — **вторая** кнопка «Читать на сайте» (`cta_kind`/url), не вместо заявки.
3. В тексте перед кнопкой — блок «что будет, если нажмёте» (чат-бот сервиса, не СФР; без сканов; следующий шаг).  
   Формулировку кнопки в тексте синхронизировать: «Подать заявку».
4. В канале **не** принимать ПДн, сканы, индивидуальные консультации в комментариях.
5. Премодерация и daily-cron без изменений: черновик → ops → «Опубликовать».

Код: `client_cta_attachments` всегда добавляет «Подать заявку»; URL — опционально второй ряд.

## 6. Путь после «Подать заявку»

Канон bot_owned (без нового ЛК в MAX):

1. Welcome + FSM / LLM.  
2. Согласие ПДн (чат/кабинет).  
3. Документы → комплект / дозапрос.  
4. Счёт → оплата или чек.  
5. Сверка → расхождения пунктами.  
6. Согласование плана со специалистом.  
7. Дальше DOCS / SUPPORT по воротам тарифов 3/5/8.

См. `src/sfrfr/services/max_bot_funnel.py`.

## 8. Критерии готовности

1. В рекламных брифах целевой URL по умолчанию — канал, не чат.  
2. Новый пост без кнопки «Подать заявку» не публикуется (код гарантирует кнопку при наличии `MAX_CHAT_URL`).  
3. Из кнопки открывается личный бот; воронка ведёт до оплаченного результата / плана со специалистом.  
4. Нет обещаний перерасчёта; позиция подачи соблюдена.

---

## 9. Чего не делаем

- Не смешиваем канал и личный чат в одном URL.  
- Не собираем документы в канале.  
- Не делаем mini-app кабинетом.  
- Не автопубликуем без ops-review.
