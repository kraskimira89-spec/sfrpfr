спокойный ритм напоминаний о подаче/СФР + убрать ранний upsell диагностики.

## Исправлено / проверено (код + unit)

| Пункт | Результат |
|---|---|
| «Вопрос N из 4» | `ru_question_progress` → `Вопрос {n} из {total}.` |
| Вступление | Новый короткий INTRO; без извлечения/профиля MAX |
| Файл между вопросами | `_resume_questionnaire_after_upload` после ack; шаг не теряется |
| Без согласия | Приём файлов не ослаблен |
| «Дело создано» | Формулировка владельца + CASE; без diag offer после анкеты |
| E-mail | Авто-отправка на известный; `lm:change_email`; старый `USE_KNOWN` актуален |
| Ритм 4→8→12 | `submission_nudge` + поля intake; restart копирует счётчик |
| Gate 3000 ₽ | `diag_offer_gate` + `MAX_DIAG_OFFER_EF_OPEN=0`; старый `diag:yes` → `diag_yes_gated` |
| Soft чек-лист/share | `soft_offers`, проверенный `LEAD_MAGNET_BOT_URL`, без фоновых рассылок |
| Web scroll | Кабинет уже `scrollIntoView` на новое сообщение |
| MAX scroll | Бот не управляет прокруткой клиента — только новое сообщение в конец |

## Изменённые тексты (ключевые)

- INTRO: «Здравствуйте! Поможем разобраться… четыре коротких вопроса…»

## Живой MAX-smoke (для владельца)

1. Согласие → анкета: видны «Вопрос 1..4 из 4», короткое вступление.
2. Файл между 2 и 3 → ack + повтор вопроса 3 (или текущего), без второго дела.
3. После анкеты: одно «дело CASE-… создано», **нет** кнопки «Оформить диагностику 3 000».
4. `/checklist` или soft-оффер → при известном e-mail письмо уходит без повторного вопроса; «Изменить e-mail» работает.
5. Старая кнопка `diag:yes` → отказ gate, не счёт.
6. Прокрутка в MAX: убедиться глазами, что новое сообщение в конце ленты (SDK scroll не обещаем).

## Ограничения прокрутки MAX

Платформа MAX не даёт боту гарантированно скроллить UI клиента к новому сообщению.
Опора: сообщение уходит в конец диалога. Web-кабинет — отдельный канал, scroll уже есть.
