# 2026-10-24 — статус дубля чека 8000 (разбор без нового платежа)

**Для:** Стратег / SFRFR-100
**Правило:** новый боевой платёж и новый чек **не** создавались.

## Классификация дубля

| Вопрос | Ответ |
|---|---|
| Что дублировалось? | Два самостоятельных succeeded чека **`type=payment`** на один платёж |
| Не является | парой payment+refund; повторным notify; «двумя разными услугами» |
| Причина | **установлена:** `ensure_payment_receipt` / webhook при отстающем `receipt_registration` + авточек invoice |
| Задача | SFRFR-89 |
| Доказательства | `2026-10-23-battle-support-8000.md`, `2026-10-23-receipt-dedup-ensure-gate.md` |

## Связь с SFRFR-93

Fiscal reconcile (SFRFR-93) чинит хвост **canceled** после paid.
Дубль 8000 — другой механизм (второй create receipt).
**Стоп-условие текущего наблюдения SFRFR-93 из-за дубля — нет.**

## После фикса

| Событие | Вердикт |
|---|---|
| Gate #226 + smoke 1₽ | дубль не повторился; live-гонка pending не доказана (`SMOKE_OK_RACE_UNVERIFIED`) |
| Повторный SUPPORT 8000 | 1× payment — PASS |
| PASS 3000/5000 | **не** заменяют приёмку 8000 |
| Возврат денег по PASS-8000 (2026-10-24) | **не выполнен:** ЮKassa `403 Insufficient funds` |

## Временное ограничение

Без отдельного «да, платим» / согласования — не проводить новый боевой платёж для воспроизведения.
Повторная приёмка 8000 — критерии в паспорте §4.3.
