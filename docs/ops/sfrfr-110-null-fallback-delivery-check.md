## Таблица Null / исходы

| Ситуация | Ожидание | Факт / тест |
|---|---|---|
| Адаптер не вернул фактов (Null) | Нет признания ошибки через E05 | `try_policy… is None`; `action != max_e05_f04_policy` |
| Возврат к LLM-пути | Явно: **нет** handler-enforced защиты от «исправлено» | `test_null_adapter_…`: invented phrase уходит как `max_llm_reply` (prompt-only) |
| Политика подготовила ответ | Текст не подменяется противоречием при сбое enqueue | handler шлёт **тот же** `reply.text` один раз при `enqueued=False` |
| Доставка не подтверждена | Нет второго ответа с другим смыслом | при `enqueued=True` второго `_reply` нет; `caller_outcome=delivery_unconfirmed` |

## Различимые исходы для вызывающего кода

| Код | Смысл |
|---|---|
| `no_trusted_context` | Null / не мой сценарий → перехват не применяется (`None`) |
| `insufficient_facts` | Контекст есть, ошибка не подтверждена |
| `policy_prepared` | Ответ политики сформирован |
| `delivery_unconfirmed` | Подготовлен/поставлен, транспорт или persist не подтверждён |

Не смешивать эти четыре состояния в один «fallback».

## LLM-путь при Null (честно)

Защита от неподтверждённых утверждений на обычном LLM-ответе —
**prompt / throttle**, не `TrustedErrorContext`. Это **не** ложное покрытие E05.
Отдельная задача: пост-фильтр критических фраз на `max_llm_reply` (не в этом срезе).
