Статус: **план / контракт**. Реализация кода, миграции, merge, deploy, live —
**только после отдельного разрешения.** Этот документ не является разрешением.

Зависимости контекста: канон E01; `docs/ops/sfrfr-110-e01-operation-contract.md`;
audit #265 `263d629b…`; library #261; wire #263 (TrustedOpResult / persist flags).

## Цель PR

Одна staff/job-операция, на которую затем оперется E01-ответ:

```text
команда на исправление
≠ подтверждённая запись
≠ событие period_date_corrected
≠ пересчитанный результат
≠ сообщение клиенту
```

Событие «исправлено» **не** создавать до подтверждённой записи.

## Обязательный контракт (ТЗ §6)

1. Полномочия субъекта + принадлежность записи делу.
2. Однозначная идентификация периода и поля.
3. Ожидаемая версия + `operation_id` (идемпотентность).
4. Валидация входных данных (дата, диапазон, формат).
5. before/after + основание изменения.
6. Атомарная проверка версии и запись.
7. Определённое поведение при повторе (тот же `operation_id` → тот же ack).
8. Возврат подтверждения **фактически сохранённого** результата (`TrustedOpResult` / repo ack).
9. Исправление не теряется при последующем pipeline snapshot.
10. Зависимые результаты — «требуют актуализации», без «пенсия пересчитана».
