## 2. Рекомендуемые задачи реализации (не создавать дубли)

Создавать issue **только если** нет покрывающей. Кандидаты (черновик для Стратега):

1. **Wire reply-from-events** — выбор E01–E21 только при наличии фактов; иначе safe uncertainty.  
2. **Claim intake before full evidence** — регистрация требования из чата без доказательства всей ошибки.  
3. **Provisional needs_recheck** — адресное ограничение до подтверждения; не announce как «ошибка подтверждена».  
4. **Dual fix planes** — отдельные статусы cause_fixed / consequences_checked; запрет «всё исправлено» при одном из них.  
5. **Evidence card storage audit** — решить: расширение существующего store vs новая сущность; **без** миграции до аудита.  
6. **Notification transition** — отдельные события prepared → available → sent → delivery_status.  
7. **Handler regression** — JSON/QA из `docs/qa/client-ai-error-scenarios.md` против live-ответов (staging), без ПДн.

Связанный открытый контур: **SFRFR-110**. Не закрывать SFRFR-110 этим docs-PR.
