## 2. Refund 8000 ₽ / баланс ЮKassa

Два **разных** действия — не считать одно решением другого:

| Действие | Что делает | Что не делает |
|---|---|---|
| **R1. Возврат денег** | `POST` refund в ЮKassa на сумму возврата | Не удаляет и не «склеивает» уже выбитые чеки прихода |
| **R2. Фискальная корректировка / разбор дубля чека** | Отдельная политика по двум `type=payment` (SFRFR-89) | Не возвращает деньги сама по себе |

### Основание возврата

| Поле | Факт |
|---|---|
| Основание | Повторный боевой SUPPORT 8000 (PASS 2026-10-23) — тестовый платёж владельца; деньги клиенту/тестовой карте подлежат возврату по команде «верни 8000» |
| Точная сумма к возврату | **8000.00 RUB** (полный refund одного платежа) |
| Shop | **1421177** (боевой) |
| Текущий статус платежа (на момент отказа) | `succeeded`, `refunded_amount=0.00` |
| Чеки | 1× `type=payment` succeeded; **0×** `type=refund` |
| Попытка возврата 2026-10-24 | HTTP **403** `Insufficient funds to make a refund` — деньги **не** списаны/не возвращены |
| Доступный баланс | Недостаточен для refund 8000 (точный остаток в кабинете ЮKassa — смотрит владелец; Кодер API баланс не читал повторно в этом отчёте) |

### Варианты решения владельца

| Вариант | Шаги | Риск |
|---|---|---|
| **V1 (рекомендуется)** | Пополнить баланс shop 1421177 → отдельная команда «верни 8000» → Кодер делает только R1 → сверка `refunded_amount` + чек `type=refund` | Низкий, если сумма = 8000.00 |
| **V2** | Обратиться в поддержку ЮKassa (причина «нет средств на refund после выплаты») → затем V1 | Задержка |
| **V3** | Отложить возврат | Клиент/карта без денег; задача C2 открыта |
| **V4** | Параллельно решать дубль чека (R2) | **Только** отдельным «да»; не смешивать с R1 |

### Что подтвердить одной фразой

1. «Пополнить баланс 1421177 — да/нет / сделаю сам».  
2. После пополнения: «верни 8000» = разрешение **только на R1** (refund API).  
3. R2 (чеки/дубль): отдельное явное разрешение или «не трогать чеки».
