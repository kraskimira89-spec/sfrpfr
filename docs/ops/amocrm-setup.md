# Настройка amoCRM для SFRFR (по шагам)

**Для кого:** владелец аккаунта / администратор amoCRM + тот, кто правит `/opt/sfrfr/.env` на VPS.  
**Код:** `src/sfrfr/integrations/amocrm/` · **ТЗ:** [../specs/12-amocrm.md](../specs/12-amocrm.md)  
**Доки amo:** [OAuth по шагам](https://www.amocrm.ru/developers/content/oauth/step-by-step), [custom fields](https://www.amocrm.ru/developers/content/crm_platform/custom-fields), [leads API](https://www.amocrm.ru/developers/content/crm_platform/leads-api)

Цель: чтобы заявка с сайта создавала в amo **сделку + контакт** с полем `CASE_ID`, без сканов и СНИЛС.

---

## Что получите в итоге

| Где | Что |
|-----|-----|
| amoCRM | Приватная интеграция «SFRFR», долгосрочный токен |
| amoCRM | Воронка «Проверка стажа» + этап «Новый лид» |
| amoCRM | Доп. поля сделки с кодами `CASE_ID`, … |
| VPS `.env` | `AMO_SUBDOMAIN`, `AMO_ACCESS_TOKEN`, `AMO_PIPELINE_ID`, `AMO_STATUS_ID` |
| CLI | `sfrfr amocrm-ensure-fields` и тестовый sync |

---

## Шаг 0. Аккаунт

1. Войдите в amoCRM под пользователем с правами **администратора**.
2. Запомните **поддомен** из адресной строки:  
   `https://ВАШ_ПОДДОМЕН.amocrm.ru/` → это значение `AMO_SUBDOMAIN`  
   Пример: `https://proverkastaza.amocrm.ru/` → `AMO_SUBDOMAIN=proverkastaza`.

⚠️ Приватная интеграция на обычном (не техническом) аккаунте требует **заявления об отказе от техподдержки amo** по ошибкам системы (раз и навсегда). Консультации по оплате обычно не затрагиваются. См. раздел «Регистрация приложения» в [доке OAuth](https://www.amocrm.ru/developers/content/oauth/step-by-step).

---

## Шаг 1. Создать интеграцию (амоМаркет)

**Где в интерфейсе:** левое меню → **амоМаркет** (или «Настройки» → интеграции / маркет, в зависимости от версии UI).

1. В правом верхнем углу раздела амоМаркет нажмите **⋯** (три точки).
2. Выберите **Создать интеграцию**.
3. Тип: **внешняя / приватная** (для своего аккаунта, не публичная в каталоге).
4. Заполните форму:

| Поле | Что указать |
|------|-------------|
| Название | `SFRFR` |
| Описание | `Синхронизация лидов проверки стажа (case_id). Без файлов.` |
| Redirect URI | `https://proverkastaza.ru/` (нужен рабочий HTTPS; для долгосрочного токена обмен кода не используем, но поле обязательное) |
| Предоставить доступ | минимум: **сделки**, **контакты** (чтение и запись). При наличии галок — «пользователь» не обязателен |
| Иконка | любая 400×272 (можно логотип сайта) |
| Хук отключения | можно пусто |

5. Сохраните. Интеграция появится в списке **Установленные**.

Ссылки на доки: свойства интеграции и доступы — [OAuth step-by-step → Регистрация приложения](https://www.amocrm.ru/developers/content/oauth/step-by-step).

---

## Шаг 2. Долгосрочный токен (рекомендуемый способ для SFRFR)

Код SFRFR ждёт **Bearer access token** в `AMO_ACCESS_TOKEN`. Для одного аккаунта удобнее **долгосрочный токен** (с февраля 2024), без refresh-цикла.

**Где:** амоМаркет → ваша интеграция **SFRFR** → вкладка **Ключи** (или «Ключи и доступы»).

1. Откройте интеграцию **SFRFR**.
2. Вкладка **Ключи**.
3. Нажмите **Сгенерировать токен**.
4. Выберите срок (для продакшена разумно **1–2 года**, максимум до 5 лет).
5. **Сразу скопируйте** токен — показывают **один раз**.
6. Сохраните в менеджер паролей / секреты; в git **не** коммитить.

Проверка прав: токен действует от имени пользователя, который выдал доступ. Выдавайте под учёткой админа/оператора, которому можно создавать сделки.

Отозвать: вкладка **Выданные доступы** → **Отозвать доступ**.

Источник: раздел «Долгосрочные токены» в [OAuth step-by-step](https://www.amocrm.ru/developers/content/oauth/step-by-step).

## Шаг 3. Воронка и этап «Новый лид»

**Где:** **Настройки** (шестерёнка) → **Воронки** / **Сделки** → настройка воронок  
(в части аккаунтов: меню **Сделки** → настройка воронки ⚙️).

1. Создайте воронку, например **«Проверка стажа»** (или используйте существующую).
2. Первый этап для новых заявок с сайта назовите **«Новый лид»** (или «Неразобранное»).
3. Дальнейшие этапы подстройте под операционку (пример):  
   Связались → Документы → В работе → Результат → Успешно / Отказ.  
   Зеркалирование всех этапов SFRFR в MVP **не обязательно** — код пишет `PIPELINE_STATUS` в доп. поле текстом.

### Как узнать `AMO_PIPELINE_ID` и `AMO_STATUS_ID`

**Вариант A — через API (надёжно):**

```bash
curl -s -H "Authorization: Bearer ВАШ_ТОКЕН" \
  "https://ВАШ_ПОДДОМЕН.amocrm.ru/api/v4/leads/pipelines" | jq .
```

В ответе найдите воронку → её `id` = `AMO_PIPELINE_ID`,  
у нужного статуса (этапа) поле `id` = `AMO_STATUS_ID`.

**Вариант B — из URL в браузере:**  
откройте список сделок нужной воронки / этапа; в адресе иногда видны `pipeline_id` / `status_id`. Если не видно — используйте вариант A.

Запишите оба числа — они пойдут в `.env`.

## Шаг 4. Дополнительные поля сделки

Нужны поля с **символьными кодами** (важно для API):

| Код (`code`) | Тип в UI | Название (пример) |
|--------------|----------|-------------------|
| `CASE_ID` | Текст | Case ID (SFRFR) |
| `SFRFR_CASE_URL` | Ссылка | Ссылка на дело SFRFR |
| `PIPELINE_STATUS` | Текст | Pipeline status |
| `CHANNEL` | Текст | Канал клиента |
| `SOURCE` | Текст | Источник лида |
| `CONSENT` | Флаг / checkbox | Согласие на связь |

### Вариант A — автоматически (предпочтительно)

После шага 5 (env на VPS):

```bash
cd /opt/sfrfr && . .venv/bin/activate
sfrfr amocrm-ensure-fields
```

Команда создаст недостающие поля через `POST /api/v4/leads/custom_fields` ([дока](https://www.amocrm.ru/developers/content/crm_platform/custom-fields)).

### Вариант B — вручную в UI

**Где:** **Настройки** → **Настройка полей** (или Сделки → настройка полей карточки).

1. Сущность: **Сделки**.
2. Группа (опционально): **SFRFR**.
3. Создайте поля из таблицы выше.
4. В карточке каждого поля задайте **символьный код** ровно как в таблице (`CASE_ID`, не `case_id`).
5. Вынесите поля на карточку сделки (видимость в форме), чтобы оператор видел Case ID и ссылку.

⚠️ Телефон и email — **стандартные** поля контакта (`PHONE` / `EMAIL`); отдельно создавать не нужно.

## Шаг 5. Переменные на VPS

**Где:** файл `/opt/sfrfr/.env` (только root/deploy), затем `systemctl restart sfrfr-api`.

```env
AMO_SUBDOMAIN=ваш_поддомен
AMO_ACCESS_TOKEN=вставьте_долгосрочный_токен
AMO_PIPELINE_ID=1234567
AMO_STATUS_ID=12345678
AMO_CASE_URL_TEMPLATE=https://{subdomain}.amocrm.ru/leads/detail/{id}
```

| Переменная | Откуда |
|------------|--------|
| `AMO_SUBDOMAIN` | шаг 0 |
| `AMO_ACCESS_TOKEN` | шаг 2 |
| `AMO_PIPELINE_ID` | шаг 3 |
| `AMO_STATUS_ID` | шаг 3 |
| `AMO_CASE_URL_TEMPLATE` | обычно не менять |

Перезапуск:

```bash
sudo systemctl restart sfrfr-api
curl -fsS http://127.0.0.1:8011/health
```

## Шаг 6. Проверка end-to-end

1. Создать поля: `sfrfr amocrm-ensure-fields` → в ответе `"ok": true`.
2. Синк существующего дела:  
   `sfrfr amocrm-sync --case-id <uuid>`  
   → в JSON есть `lead_id` и `crm_url`.
3. В amoCRM откройте сделку по ссылке: есть контакт, телефон/email, поле **CASE_ID**.
4. Отправьте тестовый лид с сайта (или `POST /api/public/leads` с токеном) → новая сделка в этапе «Новый лид».
5. В admin SFRFR у дела должна появиться ссылка CRM (`crm_url`), если сохранился `crm_external_id`.

Если токен не задан — API отвечает `amocrm.skipped=true`, дело всё равно создаётся (как у Taganay).

---

## Шаг 7. Права операторов в amo (рекомендации)

**Где:** **Настройки** → **Пользователи**.

1. Операторам — доступ к воронке «Проверка стажа».
2. Не давайте лишним людям право админа интеграции (токены видят только админы аккаунта-разработчика).
3. В карточке сделки оператор работает с этапом и заметками; **сканы** по-прежнему только в SFRFR / MAX.

---

## Чего не делать в amo

- Не создавать поля под СНИЛС, паспорт, ИЛС.
- Не грузить сканы в поле типа «Файл» amo.
- Не коммитить `AMO_ACCESS_TOKEN` в git.
- Не светить токен в WordPress / браузерном JS.

---

## Чеклист приёмки

- [ ] Интеграция SFRFR создана в амоМаркете
- [ ] Долгосрочный токен сохранён в `/opt/sfrfr/.env`
- [ ] Воронка и этап «Новый лид» → ID прописаны в env
- [ ] `sfrfr amocrm-ensure-fields` успешен
- [ ] Тестовая сделка с `CASE_ID` видна в amo
- [ ] Лид с сайта создаёт сделку без ошибок API
- [ ] В admin есть кликабельный `crm_url`

## Справка: куда кликать (карта)

```text
amoCRM
├── амоМаркет → ⋯ → Создать интеграцию → SFRFR     ← шаг 1
│                 → Ключи → Сгенерировать токен      ← шаг 2
├── Настройки → Воронки / этапы сделок               ← шаг 3
├── Настройки → Поля сделок (или CLI ensure-fields)  ← шаг 4
└── Сделки → карточка (проверка CASE_ID)             ← шаг 6

VPS
└── /opt/sfrfr/.env + systemctl restart sfrfr-api     ← шаг 5
    sfrfr amocrm-ensure-fields / amocrm-sync         ← шаг 6
```

---

## Вне scope этой инструкции

- Входящие webhooks amo → смена статуса в SFRFR.
- Публикация интеграции в каталог амоМаркета.
- Автообновление OAuth refresh (при долгосрочном токене не нужно до даты окончания).
