### Подтверждение техподдержки amoCRM (2026-07-26)

План SFRFR **одобрен** поддержкой:

- приватная интеграция + долгосрочный токен + API v4 с сервера — корректный способ;
- для `POST /api/v4/leads/complex` и `POST /api/v4/leads/custom_fields` достаточно **админа** или пользователя с правами создавать/редактировать сделки и поля;
- для **приватной** интеграции **не требуются** публичная модерация и отдельное заявление об отказе от поддержки (уточнение поддержки; в старой доке OAuth формулировка жёстче — ориентируемся на ответ поддержки для нашего кейса).

---

## API vs веб-интерфейс (важно)

Через API amoCRM можно **добавлять и менять значения полей** в карточках сделок/контактов/компаний и **управлять частью настроек** (например, создавать доп. поля).  
**Не всё** меняется через API: интеграция в амоМаркете, выпуск токена, часть UI-настроек воронок/прав, сложные формулы — только вручную в веб-интерфейсе.

| Задача SFRFR | Через API? | Как у нас |
|--------------|------------|-----------|
| Создать интеграцию «SFRFR», Redirect URI, доступы | ❌ только UI | шаг 1 |
| Сгенерировать долгосрочный токен | ❌ только UI | шаг 2 |
| Создать воронку / переименовать этапы «как удобно оператору» | ⚠️ API есть, но в MVP **вручную** | шаг 3 |
| Узнать `pipeline_id` / `status_id` | ✅ `GET /leads/pipelines` | шаг 3 |
| Создать доп. поля с `code` (CASE_ID и др.) | ✅ | `sfrfr amocrm-ensure-fields` или UI шаг 4 |
| Создать/обновить сделку + контакт + значения полей | ✅ | код `integrations/amocrm` при лиде/этапе |
| Права пользователей, вид карточки, формулы | ❌ только UI | шаг 7 |
| Загрузка сканов / СНИЛС в amo | не делаем | запрещено ТЗ-12 |

Итого для запуска: **шаги 1–3 и 7 — руками в amo**; поля (шаг 4) и ежедневный sync — **через API**.

## Цель настройки

Заявка с сайта / API создаёт в amoCRM **сделку + контакт** с доп. полем `CASE_ID` (= UUID дела SFRFR).  
Сканы, СНИЛС, ИЛС, OCR в amo **не** передаются.

| # | Где настраивать | Что сделать |
|---|-----------------|-------------|
| 0 | Адресная строка браузера | Записать поддомен → `AMO_SUBDOMAIN` |
| 1 | **амоМаркет** → ⋯ → Создать интеграцию | Интеграция «SFRFR», доступы к сделкам и контактам |
| 2 | Интеграция → вкладка **Ключи** | **Сгенерировать токен** (долгосрочный) → `AMO_ACCESS_TOKEN` |
| 3 | **Настройки** → воронки сделок | Воронка + этап «Новый лид» → `AMO_PIPELINE_ID`, `AMO_STATUS_ID` |
| 4 | Поля сделок (UI или CLI) | Коды `CASE_ID`, `SFRFR_CASE_URL`, … |
| 5 | VPS `/opt/sfrfr/.env` | Прописать 4 переменные, перезапустить API |
| 6 | CLI на VPS + UI amo | `amocrm-ensure-fields`, тестовый sync, проверка карточки |
| 7 | **Настройки** → пользователи | Права операторов на воронку |

## Шаг 0. Аккаунт и поддомен

**Где:** браузер, URL вашего amo.

1. Войдите под пользователем с правами **администратора** (или с правом создавать/редактировать сделки и поля — по ответу поддержки amo).
2. В адресной строке: `https://ВАШ_ПОДДОМЕН.amocrm.ru/`  
   Пример: `https://proverkastaza.amocrm.ru/` → в env будет `AMO_SUBDOMAIN=proverkastaza`.

ℹ️ По ответу поддержки (2026-07-26): для **приватной** интеграции отдельное заявление об отказе от техподдержки **не требуется**. Если при создании интеграции UI всё же покажет такое соглашение — прочитайте текст внимательно перед принятием (в публичной доке OAuth формулировка строже).

## Шаг 1. Создать интеграцию в амоМаркете

**Где кликать:**

1. Левое меню → **амоМаркет** (в части интерфейсов: магазин приложений / интеграции).
2. В **правом верхнем углу** раздела нажмите **⋯** (три точки).
3. **Создать интеграцию**.

**Что заполнить в форме** ([дока](https://www.amocrm.ru/developers/content/oauth/step-by-step)):

| Поле формы | Значение для SFRFR |
|------------|-------------------|
| Название | `SFRFR` |
| Описание | `Синхронизация лидов проверки стажа по case_id. Без файлов и СНИЛС.` |
| Redirect URI | `https://proverkastaza.ru/` (обязательное поле; для долгосрочного токена обмен `code` не используем, но URI должен быть валидным HTTPS) |
| Предоставить доступ | **Сделки** — чтение и запись; **Контакты** — чтение и запись |
| Логотип | любая картинка по требованиям формы (часто ~400×272) |
| Хук об отключении | можно не заполнять |

4. Сохраните. Интеграция появится среди установленных; у неё появятся **Integration ID** и **Secret key** (для полного OAuth; при долгосрочном токене в SFRFR не обязательны).

---

## Шаг 2. Долгосрочный токен (основной способ для SFRFR)

С февраля 2024 amo позволяет выпускать **долгосрочные токены** для внешних/приватных интеграций: срок **от 1 дня до 5 лет**, **без** `refresh_token` ([дока → «Долгосрочные токены»](https://www.amocrm.ru/developers/content/oauth/step-by-step)).

**Где кликать:**

1. **амоМаркет** → откройте интеграцию **SFRFR**.
2. Вкладка **Ключи**.
3. Кнопка **Сгенерировать токен**.
4. Выберите дату окончания (для продакшена разумно **1–2 года**).
5. **Сразу скопируйте** токен — показывают **один раз**.
6. Сохраните в **`secrets/amocrm.env`** (папка `secrets/` в `.gitignore`) и продублируйте на VPS в `/opt/sfrfr/.env` как `AMO_ACCESS_TOKEN`.  
   **Не** использовать «Секретный ключ» и «Код авторизации» (код ~20 минут) — для SFRFR нужен именно блок **«Долгосрочный токен»**.

Запросы к API: заголовок `Authorization: Bearer {токен}` (так же работает код SFRFR / `AMO_ACCESS_TOKEN`).

**Отозвать:** вкладка **Выданные доступы** → **Отозвать доступ**.

Проверка токена (с ПК или VPS):

```bash
curl -sS -H "Authorization: Bearer ВАШ_ТОКЕН" \
  "https://ВАШ_ПОДДОМЕН.amocrm.ru/api/v4/account"
```

Ожидается JSON с данными аккаунта, не `401`.

## Шаг 3. Воронка и этап «Новый лид»

**Где кликать (один из вариантов UI):**

- **Настройки** (шестерёнка) → **Воронки** / настройка воронок сделок;  
  или  
- **Сделки** → иконка настройки воронки ⚙️.

**Что сделать:**

1. Создайте воронку **«Проверка стажа»** (или выберите существующую под лиды с сайта).
2. Первый этап для заявок с витрины назовите **«Новый лид»** (или оставьте «Неразобранное»).
3. Остальные этапы — под вашу операционку, например:  
   Связались → Документы → В работе → Результат → Успех / Отказ.  
   Полное совпадение имён этапов с `pipeline_status` SFRFR в MVP **не обязательно**: статус дополнительно пишется текстом в поле `PIPELINE_STATUS`.

> **Факт на аккаунте proverkastaza:** воронка = «Проверка стажа» (`AMO_PIPELINE_ID=11140950`).  
> Системный этап «Неразобранное» **нельзя** переименовать через API (`is_editable: false`) — создан отдельный этап **«Новый лид»** (`AMO_STATUS_ID=87464262`).  
> Скрипт: `scripts/amocrm_rename_pipeline.py` (ещё раз гонять не обязательно).

### Как получить числа для `.env`

**Вариант A — API (предпочтительно):**

```bash
curl -sS -H "Authorization: Bearer ВАШ_ТОКЕН" \
  "https://ВАШ_ПОДДОМЕН.amocrm.ru/api/v4/leads/pipelines"
```

- `id` воронки «Проверка стажа» → `AMO_PIPELINE_ID`
- внутри `statuses[]` у этапа «Новый лид» поле `id` → `AMO_STATUS_ID`

**Вариант B — из URL:** откройте колонку этапа в сделках; иногда в адресе видны `pipeline_id` / `status_id`. Если нет — только вариант A.

Если `AMO_PIPELINE_ID` / `AMO_STATUS_ID` не задать, amo создаст сделку в **первом этапе главной воронки** (поведение API по умолчанию).

## Шаг 4. Дополнительные поля сделки (custom fields)

Нужны поля с **символьным кодом** (`code`) — по ним код SFRFR пишет значения через `field_code` ([дока custom fields](https://www.amocrm.ru/developers/content/crm_platform/custom-fields)).

| Код | Тип в amo | Название в карточке | UI |
|-----|-----------|---------------------|----|
| `CASE_ID` | Текст | ID дела (SFRFR) | видно |
| `SFRFR_CASE_URL` | Ссылка (url) | Ссылка на дело SFRFR | видно |
| `PIPELINE_STATUS` | Текст | Статус пайплайна SFRFR | видно |
| `CHANNEL` | Текст | Канал клиента | видно |
| `SOURCE` | Текст | Источник лида | видно |
| `CONSENT` | Флаг | Согласие на связь | видно |
| `FIRST_SOURCE` / `LAST_SOURCE` | Текст | Первый / последний источник | видно |
| `UTM_MEDIUM` … `UTM_TERM` | tracking_data | системные `utm_*` (имя не меняется) | скрыто (amo) |
| `LANDING_VARIANT` | Текст | Вариант лендинга | видно |
| `AUDIENCE_SEGMENT` | Текст | Сегмент аудитории | видно |
| `REGION_BUCKET` | Текст | Регион (корзина) | видно |
| `REFERRAL_CODE` | Текст | Реферальный код | видно |
| `PROBLEM_TYPE` | Текст | Тип проблемы | видно |
| `LOSS_REASON` | Текст | Причина потери | видно |
| `DIAGNOSTIC_PAID_AT` … `SUCCESS_FEE_*` | Текст | Черновик (оплаты / success fee) | **скрыто** (`is_api_only`) |

`sfrfr amocrm-ensure-fields` создаёт недостающие поля и **синхронизирует** русские названия + скрытие черновиков. UTM-поля amo (`tracking_data`) переименовать нельзя — уже скрыты системой.

Телефон и email — **стандартные** поля контакта (`PHONE` / `EMAIL`); создавать не нужно.

### Вариант A — CLI (предпочтительно)

Сначала выполните **шаг 5** (env), затем на VPS:

```bash
cd /opt/sfrfr && . .venv/bin/activate
sfrfr amocrm-ensure-fields
```

Команда создаст недостающие поля (`POST`) и обновит названия / `is_api_only` (`PATCH`).

### Вариант B — вручную в UI

**Где:** **Настройки** → **Настройка полей** / поля карточки **Сделки**  
(формулировка зависит от версии интерфейса).

1. Сущность: **Сделки**.
2. Опционально группа: **SFRFR**.
3. Создайте 6 полей из таблицы.
4. В каждом поле задайте **символьный код** точно: `CASE_ID` (не `case_id`).
5. Выведите `CASE_ID` и `SFRFR_CASE_URL` на карточку сделки, чтобы оператор видел связь с кабинетом.

## Шаг 5. Прописать секреты на VPS

**Где:** файл `/opt/sfrfr/.env` (не в git).

```env
AMO_SUBDOMAIN=ваш_поддомен
AMO_ACCESS_TOKEN=вставьте_долгосрочный_токен
AMO_PIPELINE_ID=1234567
AMO_STATUS_ID=12345678
AMO_CASE_URL_TEMPLATE=https://{subdomain}.amocrm.ru/leads/detail/{id}
```

| Переменная | Откуда взяли |
|------------|--------------|
| `AMO_SUBDOMAIN` | шаг 0 |
| `AMO_ACCESS_TOKEN` | шаг 2 |
| `AMO_PIPELINE_ID` | шаг 3 |
| `AMO_STATUS_ID` | шаг 3 |
| `AMO_CASE_URL_TEMPLATE` | оставить как в примере |

```bash
sudo systemctl restart sfrfr-api
curl -fsS http://127.0.0.1:8011/health
```

## Шаг 6. Проверка end-to-end

**Где:** SSH на VPS + UI amo → **Сделки**.

1. `sfrfr amocrm-ensure-fields` → в ответе `"ok": true` (или список уже существующих кодов).
2. `sfrfr amocrm-sync --case-id <uuid>` → в JSON есть `lead_id`, `crm_url`.
3. Откройте `crm_url` в браузере: сделка + контакт, заполнено **CASE_ID**.
4. Тестовый лид с сайта (или `POST /api/public/leads` с `X-Public-Lead-Token`) → новая сделка в этапе «Новый лид».
5. В admin SFRFR у дела появляется ссылка CRM (`crm_url`), если записался `crm_external_id`.

Если токен не задан — в ответе API будет `amocrm.skipped`, дело в SFRFR всё равно создаётся.

---

## Шаг 7. Права операторов

**Где:** **Настройки** → **Пользователи**.

1. Выдайте операторам доступ к воронке «Проверка стажа».
2. Не делайте лишних людей администраторами аккаунта (они увидят ключи интеграции).
3. Сканы документов — только в SFRFR / MAX, не в amo.

## Карта кликов (шпаргалка)

```text
amoCRM
├── амоМаркет
│   ├── ⋯ → Создать интеграцию → «SFRFR»          ← шаг 1
│   └── SFRFR → Ключи → Сгенерировать токен       ← шаг 2
├── Настройки → Воронки / этапы сделок            ← шаг 3
├── Настройки → Поля сделок  (или CLI)            ← шаг 4
├── Настройки → Пользователи                      ← шаг 7
└── Сделки → карточка (CASE_ID, контакт)          ← шаг 6

VPS
└── /opt/sfrfr/.env + restart sfrfr-api           ← шаг 5
    sfrfr amocrm-ensure-fields / amocrm-sync      ← шаг 6
```

---

## Чего не делать

- Не заводить в amo поля под СНИЛС, паспорт, ИЛС.
- Не грузить сканы в поле типа «Файл» amo.
- Не коммитить `AMO_ACCESS_TOKEN` в репозиторий.
- Не вставлять токен в WordPress, GTM, фронт кабинета.

---

## Чеклист приёмки

- [ ] Интеграция **SFRFR** создана в амоМаркете  
- [ ] Долгосрочный токен лежит в `/opt/sfrfr/.env`, `curl …/api/v4/account` = 200  
- [ ] Воронка и этап «Новый лид» → ID в env  
- [ ] `sfrfr amocrm-ensure-fields` успешен  
- [ ] Тестовая сделка с `CASE_ID` видна в amo  
- [ ] Лид с сайта создаёт сделку  
- [ ] В admin SFRFR кликабельный `crm_url`  

---

## Вне scope этой инструкции

- Входящие webhooks amo → смена статуса в SFRFR (обратный sync).
- Публикация виджета в каталог амоМаркета.
- Полный OAuth с `refresh_token` (при долгосрочном токене не нужен до даты окончания).
