# Модель переходов: сказано → выполнено → подтверждено

Дата: 2026-10-24 · SFRFR-110 · §49–59  
Логическая модель. Сопоставление с **существующим** кодом; новая схема БД не вводится без доказанного пробела.

## Три независимых результата (§49)

| Область | Код-якорь (сейчас) | Не закрывает автоматически |
|---|---|---|
| Пенсионное дело | выводы/отчёт, официальный ответ | заказ, offer, чат |
| Услуга / заказ | обязательства тарифа, выдача материалов | учёт стажа / перерасчёт |
| Разговор | ответ на вопрос, согласованный шаг | статусы заказа и дела |

Код: `ResultDomain` в `transition_contract_policy.py`.

## Карта логических переходов ↔ существующее

| Логический этап | Существующее | Недостаточно |
|---|---|---|
| Сбор документов | ingest статусы, buckets | «файл загружен» без читаемости |
| Комплект | `ClientCaseStatus.missing` / `kit_ready_no_analysis` | кнопка «всё ок» |
| Проверка запланирована | `check_status=queued` | фраза ИИ «начинаем» |
| Выполняется | `check_status=running` | показывать `queued` как running (SFRFR-83) |
| Предварительный результат | `result_ready` + сохранённый артефакт | конец вызова LLM |
| Эксперт / staff | `staff_active`, очередь staff | «передано» без задачи |
| Подача | отдельное подтверждение отправки | «я отправил» / кнопка без факта |
| Ответ СФР | документ ответа в деле | истёк ожидаемый срок |

## Развилки после проверки (§51)

A расхождение → план → действие (не «прибавка»).  
B мало данных → точечный запрос → recheck dependents.  
C противоречие → оба источника → specialist / uncertainty.  
D не подтверждено → объяснить объём → конец услуги **или** обоснованное уточнение (не новый этап ради воронки).

## Параллельные процессы (§53)

Тревога / агрессия / претензия / отказ offer / пауза / возврат / удаление / специалист / новый doc / запрет рекламы — меняют **свою** область; не молча меняют доказательства и выводы дела.

## Контракт перед действием (§54)

`transition_gate(...)` — 10 шагов; при ошибке — предыдущее состояние + факт неуспеха; неизвестный исход внешней операции → сверка, не слепой повтор.

## Актуальность (§55)

Как в contradiction/lost_doc: dependents → `needs_recheck`. Поданное обращение ≠ авто-досылка во внешнюю систему.

## Завершения (§58)

Не один флаг `success`: услуга закрыта / дело открыто / претензия отдельно / нет ответа ≠ приёмка / учёт ≠ прибавка.
