## Порядок прогона

1. **DIAG — 3000 ₽**
   Новое `is_test` дело → честное резюме / офер только с основанием → «Оформить» → оплата 3000.00 → webhook 200 → order `paid` → один payment → чек FD → MAX/кабинет without повторного оффера.
2. **DOCS — 5000 ₽**
   То же дело (после DIAG paid) или согласованное следующее → счёт 5000 → оплата → webhook → paid → чек. **Не** вводить пакет «анализ+обращения 5k» — только существующий ACCOMP/DOCS.
3. **SUPPORT — 8000 ₽**
   Сопровождение до подачи → 8000 → оплата → webhook → paid → чек.

Между шагами: зафиксировать FD / сумму / shop; при дубле FD — стоп и касса (SFRFR-89), не плодить платежи.

## Условия возврата

- Возврат **только** если в поле «владелец денег» = вернуть (или отдельное «да, возвращаем»).
- Возврат через YooKassa на тот же payment; дождаться чека `type=refund` (не путать с дублем `payment`).
- Без возврата — оставить суммы на балансе магазина 1421177 как боевую приёмку.

## Критерии шага (каждый)

- [ ] Charge API = полная сумма (3000 / 5000 / 8000), shop 1421177
- [ ] Apache `POST …/yookassa/webhook` **200** → order **paid** без reconcile
- [ ] Ровно один `payments` на order
- [ ] Чек(и): сумма позиции = charge; при паре — разобрать type payment vs refund
- [ ] `PAYMENT_TEST_AMOUNT_ENABLED=0` не меняли на 1

## Стоп-правила

- Нет «да, платим» → не создавать счёт / не оплачивать.
- Провал webhook/paid/чека → не второй счёт без Стратега.
- Не писать «тарифы приняты» до успешного прогона **всех трёх** полных сумм по этому плану.
