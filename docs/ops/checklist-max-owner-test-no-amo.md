# Чеклист: тест с одного MAX без лида в amo

**Для кого:** владелец / admin, который входит в Ops и в клиентский бот с **одного** телефона MAX.  
**Цель:** проверить клиентский UX, не создавая сделку в amoCRM и не засоряя боевую воронку.

Связано: [staff-roles-safe-ops.md](./staff-roles-safe-ops.md) · [docs/AMO/how-we-work-amocrm.md](../AMO/how-we-work-amocrm.md) · [docs/TRACKER/playbook-funnel-ops.md](../TRACKER/playbook-funnel-ops.md)

---

## 0. Запомнить модель

| Действие | Бот | Лид в amo? |
|----------|-----|------------|
| Вход в admin, approve staff | **Ops** | нет |
| `/start`, меню, FAQ в клиентском боте | **Клиентский** | обычно **нет**, пока нет handoff оператору |
| Кнопка/цель «оператор» / «передать специалисту» | **Клиентский** | **да** → `push_case_to_amocrm(..., task="max_operator")` |
| Заявка с сайта / публичный lead API | сайт | **да** |
| «Написать в MAX» из admin по чужому делу | клиентский бот | нет (ответ в существующий диалог) |

Флаг `cases.is_test` **скрывает** дело из части очередей admin, но **сейчас не блокирует** sync в amo. Без handoff оператору amo не трогаем.

---

## 1. Перед тестом

- [ ] Убедиться, что **два разных бота**: клиентский (`MAX_BOT_TOKEN`) и Ops (`MAX_OPS_BOT_TOKEN`) — оба заданы на VPS (не пустой ops = не «слитый» диалог).
- [ ] Staff-вход только через **Ops** + рабочий email из `staff_roles`.
- [ ] В amo **не** открывать виджет с личным/тестовым ботом как основным клиентским (см. `docs/AMO/ops-amocrm-max-widget.md`).
- [ ] Решить: этот прогон **без** сделки. Если нужна проверка amo — отдельный чеклист E2E, не этот.

---

## 2. Безопасный сценарий (без лида)

Делать **только** в клиентском боте, останавливаться **до** «оператор / специалист».

- [ ] Открыть диалог **клиентского** бота (не Ops).
- [ ] `/start` или приветствие — ок.
- [ ] Пройти меню / FAQ / выбор цели **кроме** «связаться с оператором» / handoff.
- [ ] При необходимости открыть **клиентский кабинет на сайте** по ссылке из бота («Кабинет на сайте») — без формы «оставить заявку» на сайте. ЛК в MAX нет.
- [ ] Проверить загрузку тестового файла **без ПДн** (пустой PDF), если нужен UX кабинета.
- [ ] **Не** жать: «оператор», «передать специалисту», intake goal `operator`.
- [ ] **Не** отправлять форму лида на сайте с тем же телефоном.
- [ ] **Не** создавать публичный lead через API «для проверки».

Ожидание: может появиться строка в `clients` / черновик дела в SFRFR — это нормально. В amo **новой сделки быть не должно**.

---

## 3. Как проверить, что лида нет

- [ ] amo → сделки: поиск по своему телефону / имени / недавним «Проверка стажа — …» за время теста.
- [ ] Admin SFRFR → если появилось дело: открыть карточку → поле CRM / `crm_url` пустое.
- [ ] Ops-бот: **нет** уведомления «Клиент ждёт ответа в MAX» по этому прогону (оно уходит вместе с amo-handoff).

---

## 4. Если всё же создали лид (срыв чеклиста)

- [ ] В admin: пометить дело **`is_test = true`** (чтобы не мешало KPI/очередям).
- [ ] В amo: сделку закрыть с причиной LOSS вроде «тест / внутренняя» **или** удалить, если политика org позволяет.
- [ ] В заметке сделки не писать лишние ПДн; достаточно `case_id` + «owner self-test».
- [ ] В Трекере (очередь **FUNNEL**): по желанию задача «разбор тестового лида» без ФИО.

---

## 5. Что тестировать с **этого же** MAX как staff (параллельно)

- [ ] Вход в admin только через **Ops**-бот / кабинет staff.
- [ ] Не путать диалоги: ответ клиентам — из admin «Написать в MAX» или виджет amo, **не** из Ops в клиентский funnel.
- [ ] Не отвечать себе как «оператор» в клиентском боте на свой же handoff — это уже боевой контур.

---

## 6. Когда этот чеклист **не** подходит

Нужен полный E2E «MAX → дело → amo» — тогда:

1. Лучше **второй** MAX (тестовый).
2. Или осознанный прогон с пометкой `is_test` + закрытие сделки в amo по [qa-lead-amocrm-e2e](../AMO/qa-lead-amocrm-e2e.md).

Отдельный staff-shield / `owner_test` в коде пока **не** реализован — опираемся на дисциплину шагов выше.

---

## 7. Короткий «нельзя»

1. Не выбирать «оператор» в клиентском боте на рабочем MAX.  
2. Не слать сайт-заявку на свой номер.  
3. Не отключать `AMO_*` на проде «чтобы не создало» — ломает боевые лиды.  
4. Не использовать Ops-бот как клиентский чат.
