## YC vs Reg.ru VM 1:1

Сравниваем **хост под Docker Compose Supabase**, не managed PostgreSQL со скрина `cloud.reg.ru`.

| Компонент | Yandex Cloud | Reg.ru VPS (публичный прайс) |
|-----------|--------------|------------------------------|
| CPU/RAM/диск | 4 / 8 / 130 ГБ SSD + IP | **High C4-M8-D120** — 4 / 8 / 120 ГБ NVMe |
| Цена хоста | **~7 525 ₽** (CPU+RAM+диски+IP) | **~4 360 ₽/мес** |
| Экономия железа | — | **~3 100 ₽/мес** |
| Auth/Storage/RLS | Compose на ВМ | то же, если перенести Compose |
| Lockbox / KMS / Object Storage | есть | заменить (файлы, свой S3/бэкап) |
| SmartCaptcha + AI Studio | usage в YC | **не переносятся** — остаются в YC |

Ближайшие альтернативы Reg.ru: High C4-M8-D80 (~3 880, диск 80 ГБ — тесно под 130 ГБ).

Managed PG Reg.ru (START-2 ~1k, START-4-8-50 ~5.8k) — **не 1:1**, без GoTrue/Storage/PostgREST.

## Сценарий A — перенос только Supabase-ВМ на Reg.ru

### Что переезжает / что остаётся

| Переезжает на Reg.ru VPS | Остаётся в Yandex Cloud |
|--------------------------|-------------------------|
| Docker Compose Supabase (Postgres, GoTrue, Storage, PostgREST, Kong/Caddy) | AI Studio / Vision (токены) |
| Данные `/data` (pg + storage files) | SmartCaptcha |
| DNS A `supabase.proverkastaza.ru` → новый IP | (опционально) Lockbox/KMS/бакет — или выключить |
| VPS API `91.229.11.147` уже на Reg.ru — меняется только `SUPABASE_URL`/ключ, если IP сменился | — |

Код кабинета/админки/API **не переписывается**: тот же `SUPABASE_URL` + JWT, только другой хост.

### Экономика железа

| | ₽/мес |
|--|------:|
| Сейчас YC хост (CPU+RAM+диски+IP) | ~7 525 |
| Reg.ru High C4-M8-D120 | ~4 360 |
| **Экономия железа** | **~3 100** |
| Residual YC (Captcha≈0 + AI usage + если оставить Lockbox/KMS) | ~40 + AI |

Итого после переноса: **~4.4k (Reg.ru) + AI usage (YC)** вместо **~7.5k + AI**.

### Объём работ (порядок 1–2 рабочих дня + репетиция)

1. Заказать VPS Ubuntu 24.04, 4/8/≥120 ГБ, Москва; открыть 443 (и SSH с вашего `/32`).
2. Поставить Docker + Compose; скопировать `/opt/sfrfr-supabase` и `/data` (или `pg_dump` + storage sync).
3. Выписать секреты из Lockbox в `.env` на новой ВМ (или Ansible/скрипт).
4. Поднять стек, Caddy/LE на том же имени или временно на IP.
5. Сменить DNS A `supabase.proverkastaza.ru` → новый IP; дождаться TLS.
6. Smoke: auth/health, REST, cabinet login (OTP), backup/restore-drill.
7. В YC: stop → через 1–2 дня destroy ВМ+диски+IP (иначе платите residual ~2.3k).
8. Бэкапы: cron `pg_dump` на диск VPS или S3-совместимое хранилище Reg.ru / оставить бакет YC.

### Риски

- Короткий простой Auth/API при DNS/TLS (минуты–час).
- Диск 120 ГБ vs текущие 130 ГБ — следить за занятостью; при росте — апгрейд тарифа.
- Нет нативного Lockbox/KMS — секреты в файлах/`chmod 600`, бэкапы шифровать самим.
- 152-ФЗ: Reg.ru РФ-ЦОД ок по ТЗ-15, если ПДн не уезжают за рубеж.

### Когда выбирать A

Нужна стабильная экономия **~3k/мес** на железе и готовы один cutover. API уже на Reg.ru — инфраструктура упрощается (всё «рядом»).

## Сценарий B — без миграции: downsize / CVoS / почему stop почти не помогает

### Почему stop почти бесполезен

При **Stop** в Compute перестают тарифицироваться только **vCPU + RAM** (~5 472 ₽).

Продолжают тарифицироваться:

| Ресурс | ~₽/мес при stop |
|--------|----------------:|
| Boot + data SSD 130 ГБ | ~1 863 |
| Public IP (неактивный = IP + резерв) | ~435 |
| Lockbox + KMS | ~42 |
| **Итого residual** | **~2 340** |

Плюс сервис **недоступен** (cabinet/auth лежат). Для прода stop на ночь = простой, не экономия. Имеет смысл только перед `destroy` или на выходных без пользователей.

Чтобы реально обнулить железо: **удалить** ВМ, диски и **освободить** статический IP (не только stop).

### Downsize в YC (оценка, те же диски 130 ГБ SSD + IP)

| Конфиг | CPU+RAM+disk+IP ~₽/мес | Экономия vs сейчас |
|--------|-----------------------:|-------------------:|
| **Сейчас 4/8 100%** | ~7 525 | — |
| 2 vCPU / 4 ГБ 100% | ~4 788 | **~2 740** |
| 2 vCPU / 4 ГБ 50% | ~4 083 | **~3 440** |
| CVoS 1 год на текущие 4/8 (ставки 1,05 / 0,28) | ~6 689 | **~835** |

Ориентир: downsize **2/4** даёт экономию того же порядка, что переезд на Reg.ru (~2.7–3.4k), **без** DNS cutover. Риск — нехватка RAM под полный Compose (Postgres + GoTrue + Storage + Realtime + Kong); нужен мониторинг `free -h` / OOM.

Урезание **диска** (data 100→50 ГБ SSD) экономит ещё ~716 ₽, но только если данные реально меньше и сделан resize/миграция тома.

Перевод data на **network-hdd** (0,0048 ₽/ГБ·ч): 100 ГБ ≈ 346 ₽ вместо 1 433 → **ещё ~1 087 ₽**, ценой IOPS (для маленькой БД MVP часто терпимо).

### CVoS (Committed Volume of Services)

- Скидка на **vCPU/RAM** при обязательстве 6/12 мес.; диски и IP **без** этой скидки.
- На текущем 4/8 выгода скромная (~0.8k/мес при 1 годе) — меньше, чем downsize или Reg.ru.
- Имеет смысл, если решили **остаться** на 4/8 в YC надолго и не хотите трогать архитектуру.

### Когда выбирать B

- Не хотите второй cutover DNS/данных.
- Готовы пожить на 2/4 и проверить нагрузку 1–2 недели.
- Или быстро: data → HDD / меньше размер диска через Terraform + окно обслуживания.

### Сводка «что выгоднее быстрее»

| Действие | Экономия ~₽/мес | Простой / риск | Срок |
|----------|----------------:|----------------|------|
| Stop ВМ | ~5.2k, но сервис мёртв; residual ~2.3k | Полный даунтайм | Мгновенно |
| Destroy после переноса | убирает residual | Нужен новый хост | После cutover |
| Downsize 2/4 | ~2.7–3.4k | Рестарт ВМ, риск OOM | Часы |
| Data → HDD | ~1.1k | Медленнее диск | Часы |
| CVoS 1y на 4/8 | ~0.8k | Контракт | В консоли |
| Reg.ru VPS 1:1 | ~3.1k железо | Cutover DNS/данные | 1–2 дня |

Рекомендуемый порядок без миграции: **сначала downsize 2/4 (или 2/4 + data HDD)** → если тесно — апгрейд обратно или сценарий A.


## Рекомендации

1. **Сверить факт** в [Биллинг](https://console.yandex.cloud/billing) → детализация за полный месяц (SA terraform без `billing.viewer`).
2. **Не менять** на managed PG Reg.ru ради «дешевле 8500».
3. Экономия: сценарии A (Reg.ru VM) и B (downsize/CVoS) выше.
4. После исчерпания гранта (~сентябрь 2026) always-on ~7.5k+usage станет реальной оплатой.
