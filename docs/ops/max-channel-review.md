# Премодерация постов клиентского канала MAX

Черновик сначала уходит в **канал специалистов**, там кнопки **Опубликовать** / **Скопировать текст**. В клиентский канал пост попадает только после «Опубликовать».

## Зачем

- Не публиковать сырой текст сразу клиентам.
- Специалист правит формулировки и CTA-блок.
- Публикует клиентский бот (`MAX_BOT_TOKEN`) — он админ клиентского канала.

## Env

| Переменная | Роль |
|---|---|
| `MAX_OPS_BOT_TOKEN` | Ops-бот «Проверка стажа-Ops» — шлёт черновик в канал команды |
| `MAX_SPECIALISTS_CHANNEL_CHAT_ID` | Канал команды (чат специалистов) |
| `MAX_BOT_TOKEN` | Клиентский бот — публикация в канал клиентов |
| `MAX_CHANNEL_CHAT_ID` | Клиентский канал (`-77580376877720`) |
| `MAX_CHAT_URL` | Ссылка на личный чат для CTA `cta_kind: chat` |

Черновики хранятся локально: `storage/max_channel_drafts.json` (в `.gitignore`).

## Команды

```powershell
.\.venv\Scripts\Activate.ps1

# один текст на одобрение
sfrfr max-channel-post --review -t "Текст черновика…"

# посты из JSON (по умолчанию --review)
sfrfr max-channel-review --only 08-ils
sfrfr max-channel-publish-starter --only 08-ils

# минуя премодерацию (только осознанно)
sfrfr max-channel-publish-starter --direct --only 08-ils
```

## Кнопки в канале команды

1. **Опубликовать** — сразу пост в канал клиентов (+ pin, если в черновике `pin: true`).
2. **Скопировать текст** — текст в буфер обмена (ограничение API MAX: в поле ввода напрямую не вставить).

Чтобы править текст: скопируйте → поправьте локально → отправьте новый черновик  
`sfrfr max-channel-post --review -t "…"`.

## Webhook

Ops-бот должен получать `message_callback` и `message_created` (как в `sfrfr max-subscribe` / ops-subscribe). После деплоя кода webhook на VPS подхватывает обработчик `chdraft:*` в `ops_bot.py`.

## Позиция в текстах

Не обещать перерасчёт / калькулятор выплат. Клиент подаёт сам через СФР / Госуслуги / МФЦ — решение принимает СФР. Канон: `scripts/assets/copy/submission-position.md`.
