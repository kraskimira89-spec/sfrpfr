# Премодерация постов клиентского канала MAX

Черновик уходит специалистам **dual** (если настроено):

1. в **канал специалистов** (`MAX_SPECIALISTS_CHANNEL_CHAT_ID`);
2. в **личку ops-бота** «Проверка стажа-Ops» (`STAFF_LOGIN_APPROVER_MAX_USER_IDS`).

Там кнопки **Опубликовать** / **Скопировать текст** / **Прислать правку**. В клиентский канал пост попадает только после «Опубликовать».

## Зачем

- Не публиковать сырой текст сразу клиентам.
- Специалисты видят очередь в общем чате команды.
- Ответственный может править и жать «Опубликовать» в личке ops.
- Публикует клиентский бот (`MAX_BOT_TOKEN`) — он админ клиентского канала.

## Env

| Переменная | Роль |
|---|---|
| `MAX_OPS_BOT_TOKEN` | Ops-бот — шлёт черновик в канал команды и/или личку |
| `MAX_SPECIALISTS_CHANNEL_CHAT_ID` | Канал специалистов (премодерация видна команде) |
| `STAFF_LOGIN_APPROVER_MAX_USER_IDS` | Кому слать черновики ещё и в личку |
| `MAX_BOT_TOKEN` | Клиентский бот — публикация в канал клиентов |
| `MAX_CHANNEL_CHAT_ID` | Клиентский канал |
| `MAX_CHAT_URL` | Ссылка на личный чат для CTA `cta_kind: chat` |

Черновики: `storage/max_channel_drafts.json` (в `.gitignore`).  
Важно: для кнопки «Опубликовать» черновик должен быть на VPS (webhook). Удобнее править текст **в личке ops** — тогда черновик создаётся на сервере.

## Команды

```powershell
.\.venv\Scripts\Activate.ps1

# dual: канал специалистов + личка ops (по умолчанию)
sfrfr max-channel-post --review -t "Текст черновика…"
sfrfr max-channel-publish-starter --only 08-ils

# только в канал команды
sfrfr max-channel-post --review --to-channel -t "…"
```

## Кнопки в личке ops / канале команды

1. **Опубликовать** — сразу в канал клиентов.
2. **Скопировать текст** — в буфер.
3. **Прислать правку** — бот ждёт следующее сообщение; вставьте правку **в этот же чат** → придёт обновлённый черновик с «Опубликовать» снова **сюда же**.

Также можно сразу вставить длинный текст поста в личку или написать `/draft …`.

## Ежедневный cron (полуавто)

См. [max-channel-daily-cron.md](max-channel-daily-cron.md): timer `sfrfr-max-channel-daily` в 10:00 МСК шлёт **один** пост на review (канал + лички). При ошибке отправки id **не** помечается sent.

## Webhook

Ops-бот: `message_callback` + `message_created` (`sfrfr max-ops-webhook-set`).

## Позиция в текстах

Не обещать перерасчёт / калькулятор выплат. Клиент подаёт сам через СФР / Госуслуги / МФЦ — решение принимает СФР.
