## Причина зависания (по фактам прогона, не гипотеза «наугад»)

Направления проверки: таймаут fetch, сброс `generating`, обновление версии, конкурирующие запросы.

**Установлено в прогоне:**

1. `POST .../full-analysis/draft` на сервере **успевал создать версию** (например v4), пока клиентский `fetch` без лимита / с коротким лимитом ещё «висел» или обрывался.
2. Кнопка оставалась в «ИИ готовит…» (`generating=true`, `disabled`), пока промис не завершался — у `apiFetch`/`staffFetch` **не было AbortSignal/таймаута**.
3. После обрыва UI **не подтягивал** уже созданный `draft` с сервера → сотрудник видел старую версию и «вечную» загрузку.

Исправление: таймаут 180с + abort; опрос state после обрыва; при повторе кнопки — подставить уже созданный draft без новой генерации; `generating` всегда сбрасывается в `finally`.

## Доказательство снятия зависания (после замечаний)

Цепочка: v4 отправлена (Диск) → «Есть замечания» → «Подготовить подробный разбор с ИИ».

| Метка | Наблюдение |
|---|---|
| 0 с | Клик → «ИИ готовит…», `disabled=true` |
| ~183 с | Кнопка снова «Подготовить…», `disabled=false` (**не зависла навсегда**) |
| Notice | «…на сервере — подставил её… повторную генерацию не запускал» (recover) |

Ранее (до фикса) статус «ИИ готовит…» сохранялся без сброса при уже созданной версии — это и был UI-разрыв.

## Полный UI-цикл (кнопки кабинета, без обхода API для шагов)

| Шаг | Канал | Результат |
|---|---|---|
| Правка / «Проверено» | UI | PASS |
| Отправка **Диск** (превью → отправить) | UI | **PASS** — `sent_via=yadisk` (v4 и v7) |
| Замечания клиента (кнопка «Есть замечания») | UI | PASS — статус `remarks` |
| Новая редакция после замечаний | UI | PASS — generating сброшен; recover с сервера |
| Устаревшее согласование (v4) | проверка API `decision` | PASS — `400 stale_or_superseded` |
| Согласование актуальной (v7) | UI «Согласовать разбор» | PASS — `approved` |
| Этап 5 / этап 6 | UI стадии | 5 ✓ «готово»; 6 ○ «Нужно согласовать…» (**не авто**) |

Решение клиента в продукте фиксируется кнопками сотрудника («Есть замечания» / «Согласовать») — отдельного SPA-экрана согласования разбора у клиента нет; доставка клиенту — Диск/почта.

## Диск

В этом прогоне канал **проверен кнопками** кабинета (не только серверным скриптом): превью ссылки → отправка → `sent_via=yadisk`.

Почту целиком повторно не гоняли (по ТЗ не требуется).
