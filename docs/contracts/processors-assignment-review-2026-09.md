## Что должно быть в поручении (ч. 3 ст. 6)

Источник: [КонсультантПлюс, ст. 6 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/315f051396c88f1e4f827ba3f2ae313d999a1873/) (ч. 3 в ред. 266-ФЗ).

1. Перечень ПДн.
2. Перечень действий (операций).
3. Цели обработки.
4. Обязанность соблюдать конфиденциальность.
5. Требования ч. 5 ст. 18 (локализация БД в РФ) и ст. 18.1.
6. Обязанность по запросу оператора, в т. ч. до начала обработки, давать документы о принятых мерах.
7. Обязанность обеспечивать безопасность и требования к защите по ст. 19.
8. Уведомление оператора об инцидентах по ч. 3.1 ст. 21 (оператор сам уведомляет РКН за 24 часа).

## Supabase, Inc. (остаточная копия) — внутренний статус

**Публичные** политика и согласие (md + HTML) с 09.10.2026 **не описывают** остаточную
копию и не называют бренд иностранного облачного провайдера БД: действующий контур —
самостоятельный в РФ (Yandex Cloud / РЕГ.РУ). Версия согласия не поднималась.

Удаление проекта Cloud `frualvycousvvyjivybu` в репозитории **по-прежнему документально
не подтверждено**: в `docs/history/project.md` / `docs/specs/15-data-localization-ru.md`
записано «Cloud проект ещё не удалён»; в `docs/ops/supabase-cloud-drain-checklist.md`
пункты drain не отмечены; акта / скрина Delete project / ответа поддержки в git нет.
Для письма в РКН нельзя писать «трансграничной передачи нет» до подтверждения —
см. [rkn-notification-2026-09.md](./rkn-notification-2026-09.md) п. 10 и чеклист
[supabase-cloud-decommission.md](../ops/supabase-cloud-decommission.md).

Что нужно владельцу для закрытия внутреннего хвоста:

1. Пройти критерии drain (API на YC, лиды пишутся только в YC, свежий бэкап и restore-drill).
2. В Supabase Dashboard сделать pause, затем **Delete project** `frualvycousvvyjivybu`;
   сохранить скриншот или PDF с датой.
3. Написать в [поддержку Supabase](https://supabase.com/dashboard/support/new): запросить
   письменное подтверждение удаления проекта и резервных копий (и срок, когда из бэкапов
   провайдера уйдут последние копии).
4. Положить ответ в юрархив, в `docs/ops/` — акт без ПДн (дата, проект, номер тикета).
5. Удалить Cloud URL и ключи из `.env`, `secrets/`, `mcp.json`; убедиться, что в проде нет
   `*.supabase.co`.
6. После подтверждения — обновить поле трансграничной передачи в черновике письма РКН
   на «не осуществляется» и закрыть чеклист decommission.
