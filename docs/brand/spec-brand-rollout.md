# ТЗ: реализация бренда v2 на сайте без поломки стилей

**Канон:** [brand-platform-v2.md](brand-platform-v2.md)  
**Промпт для агента:** [prompt-agent-brand-rollout.md](prompt-agent-brand-rollout.md)  
**Позиция о подаче:** `scripts/assets/copy/submission-position.md`  
**Стили витрины:** `scripts/assets/sfrfr-landing.css` (не ломать)

---

## 1. Цель

Внедрить голос и готовые формулировки «Цифровая рука помощи» на ключевых
публичных поверхностях так, чтобы:

- сайт остался узнаваемым и спокойным;
- CSS-токены, сетка и классы `.sfrfr-*` не ломались;
- не появилось лишних блоков, бейджей, «героев-коллажей» и маркетингового шума;
- позиция «готовим — подаёте сами — решает СФР» сохранялась дословно.

---

## 2. Принцип «без загромождения»

Разрешено:

- заменить/уточнить **текст** в уже существующих блоках (h1, lead, note, CTA-подпись);
- добавить **одну** короткую строку доверия там, где её ещё нет (класс `sfrfr-note` / `sfrfr-disclaimer`);
- мягко подправить формулировку карточки «родственники», если она уже есть.

Запрещено в этой реализации:

- новый hero full-bleed, фото-баннер, слайдер, sticky-промо;
- новые секции «миссия / ценности / бренд» на главной;
- смена палитры, шрифта, `--sfrfr-*` ради «редизайна»;
- новые карточки-ряды, pill-кластеры, emoji-иконки, бейджи «новое»;
- массовая перепись всех статей блога и situations;
- имитация Госуслуг / герб / триколор / обещание выплат;
- формулировки опеки, вины, «сыновий долг», «цифровой двойник» на витрине.

Визуал семьи (стол + экран) — **отдельный этап** (P2), только после утверждённого
ассета в `docs/brand/assets/`; до этого оставляем текущую SVG-иллюстрацию чек-листа.

---

## 3. Что не менять (жёстко)

| Объект | Правило |
|--------|---------|
| `scripts/assets/sfrfr-landing.css` | Не рефакторить. Правки CSS только если без них нельзя вписать 1–2 строки текста (макс. 10–15 строк, scoped). |
| Классы `.sfrfr-hero`, `.sfrfr-btn`, `.sfrfr-section`, сетка | Сохранить структуру DOM hero (текст слева / иллюстрация справа). |
| `{{MAX_BTN_URL}}`, `{{CABINET_URL}}`, `tel:+79091950408` | Не ломать ссылки и плейсхолдеры сидов. |
| Канон подачи | Полная или короткая формула из `submission-position.md` без «улучшений». |
| Оферта / privacy / cookies | Не трогать в этом ТЗ. |
| Массовый блог / situations | Не перегенерировать (правило blog-manual-only). |

## 4. Этапы

### P0 — копирайт приоритетных страниц (обязательно)

#### 4.1. Главная `scripts/assets/sfrfr-home.html`

| Элемент | Было (ориентир) | Сделать |
|---------|-----------------|---------|
| `h1` | «Проверим, всё ли учтено…» | **Проверим трудовую историю вместе.** |
| `.sfrfr-hero__lead` | про сверку ИЛС | **Чтобы у родителей было больше ясности, а у семьи — спокойствия.** + одна фраза-подзаголовок v2: «Поможем разобраться в сведениях о стаже, подготовить документы и понять, что делать дальше.» (можно одним абзацем из 2 предложений). |
| Primary CTA | «Уточнить ситуацию в MAX» | Оставить **как есть** (канал входа важнее новой подписи). Допустимо вторым ghost: «Начать проверку» → `#zayavka` **или** `/proverka-stazha/` — **не более одной** дополнительной кнопки; если ряд CTA уже плотный, **не добавлять**, только поправить lead. |
| `.sfrfr-disclaimer` | про СФР | Сохранить смысл; можно выровнять к блоку доверия v2: «Вы решаете сами. Мы помогаем подготовиться. Решение принимает СФР.» + при необходимости короткая отсылка «не являемся СФР». |
| Карточка про родственника в `#komu` | есть | Подправить текст к голосу v2: рядом / вместе / без опеки. Ссылка на `/pomoch-rodstvenniku-proverit-stazh/` или блог — сохранить. |
| Блок `#kak-prohodit` note | канон подачи | Не ухудшать; канон оставить. |

Hero не раздувать: не добавлять identity/channels/nav — они уже есть.

#### 4.2. Сегмент родственников `scripts/assets/trust/pomoch-rodstvenniku-proverit-stazh.html`

- Lead: взять формулировку для взрослого ребёнка v2 + канон подачи (канон уже есть — не дублировать дважды длинным абзацем).
- Рекомендуемый lead (сжато):  
  «Будьте рядом с родителем — спокойно разберитесь в цифровых вопросах вместе. Подскажем порядок действий и безопасную передачу документов — с согласия владельца данных.»  
  + **одна** короткая строка канона подачи или ссылка на `/kak-rabotaem/`.
- Карточки «Кому подходит» — слегка смягчить язык (рядом, вместе), без новых секций.
- CTA primary оставить на MAX.

#### 4.3. Услуга `scripts/assets/trust/proverka-stazha.html`

- В lead мягко вплести «трудовая история» / «яснее», **не** меняя смысл услуги и канон.
- Без новых hero/illustration.

#### 4.4. Как работаем / тарифы

- Только если в первых абзацах звучит канцелярит или давление — точечная правка 1–2 фраз.
- Канон подачи не сокращать до потери смысла.

### P1 — согласованность доверия (по желанию в том же PR)

- `kontakty.html`, `tarify.html`, `kak-rabotaem.html`: убедиться, что нет обещаний результата и опеки; канон на месте.
- Страница северного стажа: уважение к труду без плаката и без «государство должно».
- Кабинет (`apps/cabinet`): **не** редизайнить; максимум одна фраза «документы только здесь» уже в духе бренда — трогать только при явной ошибке тона.

### P2 — визуал (отдельный мини-PR, не смешивать с P0)

1. Утвердить ассет по [viz-perehod-pokoleniy.md](visualizations/viz-perehod-pokoleniy.md) → `docs/brand/assets/`.
2. На главной **заменить только** содержимое `.sfrfr-illustration` (SVG/img) на партнёрство за столом **или** оставить чек-лист, если ассета нет.
3. Подпись под иллюстрацией (опционально, мелким `.sfrfr-muted` / существующим классом):  
   «Рядом с родителями. Даже в цифровых вопросах.»  
   Не ставить как второй h1.
4. Без смены layout grid.

## 5. Готовые формулировки (копировать из v2)

- H1: **Проверим трудовую историю вместе.**
- Lead: Чтобы у родителей было больше ясности, а у семьи — спокойствия.
- Подзаголовок: Поможем разобраться в сведениях о стаже, подготовить документы и понять, что делать дальше.
- Доверие: Вы решаете сами. Мы помогаем подготовиться. Решение принимает СФР.
- Родственник: Будьте рядом с родителем — спокойно разберитесь в цифровых вопросах вместе.
- Родитель: Ваша трудовая история — достояние. Мы поможем увидеть её яснее.
- Канон подачи — из `submission-position.md`.

Редакторский тест перед каждой фразой (v2 §10): уважение к родителю + понятный следующий шаг?

## 6. Стили: чеклист «не сломать»

После правок HTML:

- [ ] Главная: hero grid на desktop — две колонки; на mobile — без горизонтального скролла.
- [ ] Кнопки `.sfrfr-btn--primary` / `--ghost` визуально как раньше.
- [ ] Нет инлайн-стилей «на глаз», кроме уже существующих единичных `margin-top`.
- [ ] Не добавлены глобальные правила вне `.sfrfr-landing`.
- [ ] Длина h1 не ломает переносы на 360px (проверить глазами / DevTools).
- [ ] Контраст текста достаточный (ink на bg).

Если нужна микроправка CSS — только scoped, например:

```css
.sfrfr-landing .sfrfr-hero__lead { /* line-height / max-width при необходимости */ }
```

Не трогать `:root` токены без крайней нужды.

## 7. Деплой и сиды

1. Править исходники в `scripts/assets/…`.
2. Коммит + push в `main` (CI `deploy-vps.yml`).
3. После деплоя кода — обновить контент WP сидом, если так принято в репо  
   (`wp_seed_site_tz02.sh` / `wp_apply_home.php` / аналог для trust-страниц).  
   Не вызывать массовый `wp_seed_blog_situations`.
4. Проверить live: `/`, `/pomoch-rodstvenniku-proverit-stazh/`, `/proverka-stazha/`.

---

## 8. Критерии готовности (P0)

- [ ] H1 и lead главной соответствуют v2 (или согласованному сжатию без потери смысла).
- [ ] Страница родственников говорит «рядом / вместе», без опеки и вины.
- [ ] Канон подачи нигде не ослаблен и не обещает подачу сервисом.
- [ ] CSS и структура hero не сломаны; новых маркетинговых секций нет.
- [ ] Нет массовых правок блога.
- [ ] История в `docs/history/` + краткий отчёт в ответе агента: список файлов и что изменилось в hero.

---

## 9. Вне скоупа

- Генерация AI-иллюстрации без отдельного запроса.
- Редизайн кабинета / меню WP / Яндекс Бизнес посты (можно отдельным ТЗ).
- Переименование юридического лица / домена.
- Смена primary CTA с MAX на абстрактную «Начать проверку», если это рвёт воронку — только как доп. ссылка или текст lead.
